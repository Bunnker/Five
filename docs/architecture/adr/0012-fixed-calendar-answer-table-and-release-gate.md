# ADR-0012：用固定日期答案表阻止错误结果上线

- 状态：Accepted
- 日期：2026-07-26
- 补充：ADR-0002

## 背景

Five 的日期、干支、五行和五档顺序会直接影响每天展示的内容。只依赖某个程序库或开发者临时查看几个日期，无法防止时区、23:00 换日、闰日或程序修改带来的错误。网页验证版虽然由一人维护，正式公开前仍需要一套不随程序修改而变化的标准答案，以及大师的人工核对记录。

## 决策

工程侧建立并固定一份日期标准答案表，覆盖 `2026-01-01` 至 `2027-01-01`（包含首尾日期，共 366 个连续 `fortuneDate`）。每一日至少记录日期、日干支、日支、日五行、五档顺序、`calendarRuleVersion` 和答案来源。答案表生成后记录生成工具版本与文件校验值，日常修改程序时不得跟随程序自动改写。

程序仍按 ADR-0002 的“国标锚点 + 公历自然日取模”规则计算；锁定版本的 `lunar-javascript@1.7.7` 只用于独立对照。每次修改日期或五行相关程序后，都必须把 366 日计算结果与固定答案表逐项比较，全部一致才能继续发布。

366 日答案表之外，另设边界答案，至少覆盖 22:59、23:00、23:59、00:00、月末、年末、闰年 02-29、早于 1949-10-01 的日期，以及程序运行在不同时区时的结果。北京时间 23:00 前后必须证明 `fortuneDate` 只切换一次。

公开试用前，大师书面核对不少于连续 30 个命理日，并核对 23:00 换日、月末、年末和闰日样本。维护者保存核对人称呼、时间、结论、备注和聊天截图或其他凭证。

任何一项机器对比或大师核对不一致，都必须暂停该日期内容的正式发布。先判断是程序错误、答案表错误，还是业务规则需要调整；需要改变规则时形成新的决策并升级 `calendarRuleVersion`，不得为了让检查通过而直接手工修改答案。

## 影响

- 首次开发需要准备 366 日答案表、边界答案和自动核对任务，但本轮技术评审只确定规则，不生成程序或数据文件；
- 日期、五行或时区相关改动必须先通过全部固定答案，才能进入公开环境；
- 大师不需要登录后台，但正式发布门槛必须能关联到其书面核对凭证；
- 未完成 366 日机器核对和大师 30 日书面核对前，只能使用内部演示数据，不能开始公开试用。
