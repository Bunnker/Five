# ADR-0007：P0 双端采用 Taro、React 与 TypeScript

- 状态：Superseded by ADR-0009 and ADR-0010
- 日期：2026-07-26

## 背景

Five 的 P0 同时交付移动端 H5 与微信小程序，两端页面层级、每日内容和验收结果高度一致，但分享、入口码、相册权限、生命周期和本地存储存在平台差异。若维护两套页面实现，容易增加交付成本并造成双端表现漂移；若忽略平台差异，又会把渠道能力错误地混入公共业务逻辑。

## 决策

P0 使用 Taro 4、React 与 TypeScript 建设一个客户端工程，由同一套页面、API 类型、状态管理和设计令牌产出 H5 与微信小程序。平台特有能力必须通过明确的平台适配层实现，不允许页面组件直接分叉日历、五行、内容版本或缓存语义。

P0 的 H5 定位为公共内容和分享落地端，不把逐个 `fortuneDate` 的搜索引擎收录、服务端渲染或动态 Open Graph 卡片作为交付门槛，也不依赖社区 SSR 插件。若未来确认这些能力为硬需求，应重新评审 H5 是否拆分为独立 Web 客户端，而不是在现有工程中隐式增加另一套渲染架构。

## 影响

- 今日首页、完整五档、搭配、模特详情、推算依据、分享和设置页面默认双端共用；
- 浏览器分享、微信分享、H5 二维码、小程序码、相册权限、前后台恢复和本地存储分别通过平台适配器实现并单独真机验收；
- 客户端不得实现 `CalendarRuleEngine`，也不得根据设备时间修改服务端返回的 `requestContext`；
- 脚手架创建时锁定 Taro 4 的具体稳定版本，依赖升级必须通过 H5 与微信小程序回归测试；
- 若单个能力无法跨端复用，可以在适配层分别实现，但不得据此复制公共页面或业务规则。
