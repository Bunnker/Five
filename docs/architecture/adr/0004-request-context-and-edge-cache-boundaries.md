# ADR-0004：请求上下文与边缘缓存边界

- 状态：Accepted
- 日期：2026-07-23

## 背景

`GET /api/v1/today` 同时返回请求上下文和每日内容，并允许 CDN 短时共享缓存。缓存正文中的时间如果被理解为“每次请求的实时服务器时钟”，会与共享缓存语义冲突；若缓存跨过午夜、时辰或内容生效边界，又会返回错误上下文。

## 决策

1. 使用 `responseGeneratedAt` 表示当前响应表示生成时刻，不使用易被误解的 `serverDateTime`。
2. `requestContext` 中的日期、命理日、时辰和跨日状态在同一时刻一次性解析。
3. 共享缓存时长：

   ```text
   N = min(
     60 秒,
     距 effectiveTo 的秒数,
     距下一时辰边界的秒数,
     距下一民用午夜的秒数
   )
   ```

4. 推荐使用 `Cache-Control: public, max-age=0, s-maxage=N, must-revalidate`，禁止过期内容跨边界复用。
5. `X-Request-Id` 由边缘层为每次外部请求生成或重写；`Date` 与 `Age` 表示缓存时间信息。
6. 客户端只消费服务端返回的上下文，不根据设备时间或 `responseGeneratedAt` 自行推进业务日期。

## 影响

- 不需要为请求上下文额外拆出一个接口；
- CDN 必须支持动态 TTL 和边界处重新验证；
- OpenAPI、缓存配置和边缘日志需要一起评审；
- 跨 23:00、民用午夜和时辰边界必须有自动化测试。
