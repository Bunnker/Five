# ADR-0027：单一维护者后台采用运营视图与语义订正

- 状态：Accepted
- 日期：2026-08-06
- 取代范围：ADR-0025 中“内容工作台默认入口为月日历”的决定
- 保留决定：ADR-0025 的月日历、用户端同构预览、结构化订正、手动上传与未来搭配图库方向

## 背景

Five 的后台只服务一名维护者。维护者每天首先需要确认今天用户看到的内容是否正常、明天是否已经准备好，以及当前有哪些可以直接处理的问题，而不是先理解草稿、版本、审核队列、生命周期状态和 JSON 载荷。月日历仍适合按日期查看内容，但不应承担每日默认入口。

现有后台还分别读取自动生产、草稿、版本和图片接口，再在浏览器中组合日期状态与预览。这会让“必备图片是否齐全”“今天是否已发布”和“明天是否已就绪”在不同页面产生不同口径。普通订正如果继续让浏览器编排创建草稿、修改模块、提交、排期和发布，也会把内部生命周期暴露给维护者，并增加中途失败后的恢复复杂度。

图片自动生产目前同时考虑两个必备槽位和一个可选槽位。可选图片不阻止公开内容，也不应消耗默认自动生产额度或被误报为异常。历史候选又可能没有可靠的 `imageSlot` 来源，不能根据上传或完成顺序猜测槽位。

## 决策

### 日常信息架构与时间

1. `/admin` 默认进入“今日”。普通后台一级导航只保留“今日”“日历”“异常”。安全设置、恢复旧版本、审计记录、高级配置和紧急控制进入“更多”或明确的高级入口。
2. “今日”同时展示“今天·用户正在看到”和“明天·准备情况”，并明确显示各自的 `fortuneDate`、状态、更新时间、两张必备图片完成度和可操作问题。两天不得共用含糊的状态标签。
3. 北京时间 18:00 只是下一 `fortuneDate` 内容准备完成的运营 SLA，不是内容生效边界。准备目标时刻由下一命理日固定 `effectiveFrom` 减五小时得到。北京时间 23:00 继续是唯一命理日切换和正常内容生效边界；跨过民用午夜不得再次推进 `fortuneDate`。
4. 月日历作为“日历”一级入口保留。日期格只显示公历日期、当日五行或主色、发布或准备状态和必备图片 `0/2` 至 `2/2`，不密集展示模特图。点击日期进入当日详情与用户端预览。
5. “异常”只展示维护者现在可以处理且会影响用户或下一次发布的问题。可选图片未请求、缺失或省略均不进入异常中心。

### 运营读模型与共享展示投影

6. 新增深模块 `AdminOperationsReadModel`。其稳定接口负责读取今日概览、月历、日期详情和可操作异常；实现内部一次组合请求上下文、内容生命周期、排期、自动生产和图片交付投影。网页适配器不再自行推导业务日期、图片完成度或发布状态。
7. `AdminOperationsReadModel` 使用一次生成的服务端 `RequestContext` 判断当前与下一 `fortuneDate`、18:00 SLA 和 23:00 边界。所有页面的日期、状态、图片数量和异常必须来自同一口径。
8. 后台手机预览与公开页面共享同一个每日展示投影模块和真实用户端展示组件。公开适配器只允许投影活跃的已发布版本；后台适配器可以投影草稿或已排期版本，并为未公开图片提供认证预览地址。不得维护第二套五档、穿搭或图片排序规则。

### 语义订正与生效

9. 普通日期详情只允许语义化订正文案、穿搭说明和图片。五档颜色、五档顺序、五行推导、`fortuneDate`、业务时间和时辰结果只读；算法错误进入独立规则订正流程，不能在单日详情覆盖。
10. 普通维护者只看到与当前日期相符的主操作：当前 `fortuneDate` 为“保存并立即替换”，未来 `fortuneDate` 为“保存并在固定 23:00 生效”。服务端根据一次解析出的 `RequestContext` 和日历固定生效窗口决定立即发布或排期，调用方不能指定另一个业务时间。
11. 语义订正背后仍创建新草稿和不可变内容版本，不覆盖已发布快照；继续保留单一活跃版本、`If-Match`、修订号、幂等键、事务内排期或替换、缓存失效意图、审计、单图下线和安全恢复。高层工作流可以组合现有领域模块，但不得在控制器或网页复制状态转换规则。

### 图片槽位

12. 默认自动生产每个命理日只请求 `required_primary` 和 `required_alternative` 两个必备封面槽位。`optional` 默认状态为 `not_requested`；维护者以后可以明确请求、上传或从搭配库选择，但可选图不阻止准备、排期或发布。
13. 必备图片始终使用固定分母 2，并区分两个口径：`modelReadyCount` 只统计仍可交付的必备模特封面，`deliverySafeCount` 统计原图或已启用的同快照安全降级素材。可选图、细节图和降级素材都不增加分母；降级时允许显示“模特图 1/2、公开交付 2/2”，并进入可行动异常。
14. 草稿图片候选的 `image_slot` 允许为 `null`，用于兼容无法可靠识别槽位的历史候选。新自动任务生成的候选必须保存明确槽位；任何 `null` 历史候选都不得按上传时间、任务完成顺序或数组位置猜测为必备或可选槽位，必须由维护者明确分配或排除在自动冻结之外。

### 兼容入口

15. 现有草稿、版本、图片审核、排期、发布、下线、恢复、审计与紧急控制接口继续作为领域能力保留。普通后台通过运营读模型和语义工作流使用它们；原始 JSON、内部编号、工程日志和低层生命周期动作只进入高级入口，不作为日常页面首要信息。
16. 后续实现如需调整 HTTP 契约，必须先更新 OpenAPI、示例和契约检查，再修改后端、Worker 与网页调用方。

## 结果

- 维护者打开后台先看到用户当前体验、明日准备状态和可处理异常，月历仍可用于跨日期维护。
- 18:00 准备 SLA 与 23:00 命理日切换不会混为同一规则。
- 日期和图片统计集中在一个模块内，删除该模块时复杂规则会重新散落到多个页面，因此该模块具有足够深度。
- 普通订正隐藏草稿和生命周期术语，但不可变版本、并发保护、审计、缓存失效、下线与恢复能力不变。
- 默认图片生产费用只覆盖两张必备图；缺少可选图不再制造错误状态。
- 历史槽位未知数据显式保持未知，避免错误图片被自动冻结到必备槽位。

## 未采用方案

- **继续以月日历作为默认入口**：不能优先回答今天是否正常和明天是否准备好，取代 ADR-0025 的这一项决定。
- **由网页组合多个低层接口并推导状态**：会复制业务日期、发布和图片口径，拒绝采用。
- **让维护者直接编辑 JSON 或选择发布状态**：暴露内部模型且容易绕过语义约束，拒绝作为普通流程。
- **自动生成第三张可选图**：可选图不影响公开可用性，默认消耗额度没有必要。
- **按候选顺序猜测历史 `image_slot`**：异步任务完成顺序不代表业务槽位，会造成错误图片发布。
