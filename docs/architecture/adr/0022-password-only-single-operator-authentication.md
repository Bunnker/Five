# ADR-0022：单一维护者统一使用账号密码登录

- 状态：Accepted（密码长度下限已由 ADR-0026 调整）
- 日期：2026-08-02
- 取代：ADR-0020 中的 TOTP、恢复码与两阶段恢复决定
- 确认记录：GitHub Issue #37；维护者明确要求所有环境统一简化

> 后续决定：ADR-0026 将本 ADR 的密码下限从 16 位调整为 8 位；其余账号密码登录与安全会话决定继续有效。

## 背景

ADR-0020 为单一维护者后台采用强密码、TOTP、恢复码和两阶段恢复。该方案安全边界完整，但首次初始化、日常登录和控制权恢复均需要额外设备与材料，不符合维护者当前对 P0 简单运营的取舍。

## 决策

后台统一使用唯一账号和强密码登录。账号密码校验成功后直接建立 30 分钟闲置、12 小时绝对上限的安全会话，不再创建密码挑战，也不再要求 TOTP。

继续保留：

- 密码长度 16 至 128 个 Unicode code point，使用带自描述参数与随机盐的 scrypt；
- 不存在账号与错误密码执行等价哈希工作量并返回统一错误；
- 请求来源级与账号级 PostgreSQL 持久化限流；
- `HttpOnly`、生产 `Secure`、`SameSite=Strict`、`Path=/admin` 的会话 Cookie；
- 可信同源 `Origin`、会话绑定 CSRF、闲置与绝对期限、当前退出和全部会话撤销；
- 登录、退出、离线重置、限流、CSRF 拒绝和紧急控制的追加安全审计。

删除 TOTP 登录、TOTP 防重放、恢复码、网页两阶段恢复及其公开接口。忘记密码时，只允许拥有服务器和数据库权限的人运行交互式离线 `reset`；新密码只从隐藏的 stdin 读取，重置时提升凭据修订号、撤销全部会话并记录审计。

紧急停止与恢复不再要求动态码，但仍必须同时满足有效会话、可信 Origin、CSRF、精确确认短语、非空原因、当前 ETag 和幂等键。内容发布、撤回与恢复原有的版本、审核、素材和审计门槛不变。

## 影响

- 登录接口直接接收账号与密码并返回会话；
- 删除密码挑战、TOTP 会话、恢复挑战和恢复完成接口；
- 管理端只保留账号密码登录，删除恢复页面入口；
- 既有数据库中的 TOTP 与恢复数据属于兼容遗留，不再参与认证，新迁移可在所有调用方移除后清理；
- 安全性从双因素降为单因素，维护者必须使用唯一强密码并保护服务器级离线重置权限。

## 未采用方案

- **仅本地免 TOTP**：会让本地与生产认证行为分叉，维护者明确要求所有环境统一简化；
- **默认账号密码**：会形成已知共享凭据，仍不采用；账号继续由离线初始化命令创建；
- **保留恢复码但删除 TOTP**：仍增加日常材料管理和网页恢复接口，未满足整体简化目标。
