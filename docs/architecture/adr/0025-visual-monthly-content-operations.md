# ADR-0025：后台采用月历式可视化内容运营

- 状态：Accepted
- 日期：2026-08-03
- 关联：[Issue #40](https://github.com/Bunnker/Five/issues/40)

## 背景

Five 由单一维护者运营。现有后台已经具备草稿、版本、自动生产、图片上传、发布、下线和恢复能力，但主要入口仍是队列、版本编号和高级 JSON。维护者需要从一个月视角确认每天是否已有内容、图片和排期，并直接看到用户端实际效果；阅读领域载荷不应成为日常操作前提。

图片供给也需要分层：默认由现有后台 Worker 调用 GPT Image 2 提前生成，生成失败或不合适时允许维护者手动上传，未来再从可复用搭配图库中按颜色组合、场景和人群选择已有模特图。

## 决定

1. 内容工作台的默认入口改为月日历，每个日期格展示日五行、生产/发布状态和图片完成度。
2. 点击日期后加载当日草稿、候选图和与公开页面共用组件构建的手机预览；维护者不需要先查询版本编号。
3. 日常订正使用结构化表单编辑五档说明、平衡建议、穿搭标题和分享文案，并继续通过现有模块 PATCH、`If-Match` 和草稿修订保存。
4. JSON 只保留在折叠的“高级设置”中，用于排障和完整载荷修改，不作为默认工作流。
5. 缺图时在日期详情中直接进入现有手动上传；正常情况下由 GPT Image 2 Worker 提前生成，用户访问时仍不实时生图。
6. P1 可增加搭配图库，以颜色组合、场景、人群、图片来源和历史表现为索引复用模特图；P0 不提前建设复杂 DAM 或新的素材领域。

## 结果

- 月历和日期详情只组合现有 API，不新增重复业务规则。
- 可视化表单保存完整模块，继续服从服务端契约和并发保护。
- 自动生成、手动上传和未来图库共用现有 `AdminImageAsset` 与来源元数据，不绑定供应商。
- 不改变不可变内容版本、发布优先、替换、下线、恢复和审计规则。
