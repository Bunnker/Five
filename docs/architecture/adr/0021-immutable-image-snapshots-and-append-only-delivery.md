# ADR-0021：不可变图片快照与追加式交付投影

- 状态：Accepted
- 日期：2026-07-31
- 补充：ADR-0003、ADR-0006、ADR-0013、ADR-0016

## 背景

每日内容在提交审核时必须冻结，但图片上线后仍可能因颜色、质量、版权、肖像或 AI 标识问题需要立即停止公开。如果直接替换已冻结快照中的 `assetId`，大师核对对象、文件校验值和历史公开内容将无法追溯；如果只能撤回整天内容，又会让仍然正确的日期、五行和文字一起不可用。

“每天 2 张必备图、最多 1 张可选图”描述的是公开方案的封面槽位，不是当天全部图片文件。方案详情使用的细节图、审核降级卡片和原始候选素材不计入 2+1。

## 决策

`ContentSnapshotPayload` 冻结每个公开方案的封面槽位、封面素材、细节素材和审核降级素材引用：

1. `required_primary` 是以大吉色为主的必备主方案；
2. `required_alternative` 是大吉色与次吉色组合的必备替代方案；
3. `optional` 是最多一个可省略的补充方案；
4. 2+1 只统计上述封面槽位，`detailAssetIds` 继续使用现有兼容上限，不参与槽位数量计算；
5. 各槽位的 `coverAssetId` 分别唯一，不能把同一张封面重复计入 2+1；
6. 每个必备槽位必须引用同一快照内与 `coverAssetId` 不同、已经上传、完成权利检查并人工审核通过的 `fallbackAssetId`；可选槽位的降级素材可为空，非空时仍满足相同安全条件。

图片文件先以 `draftId + fortuneDate` 上传，每张素材至少保存一个来源材料引用和一个权利记录引用。`ai_generated` 只与 `codex`、`relay`、`external_tool` 组合，`licensed` 只与 `licensed_upload`、`owned_upload` 组合，`fallback_template` 只与同名生成方式组合。上传、逐图审核和草稿模块保存都使用草稿 ETag；上传与逐图审核还必须使用 `Idempotency-Key`。提交草稿时，系统在同一事务中冻结图片引用并追加 `contentVersion` 绑定事件，之后不得向该快照补入或替换新素材。从旧版本复制草稿时可以复用相同文件和审核结果，但候选必须标记 `reviewLocked`，不能让新草稿的审核动作改写共享素材或旧版本的事实；需要调整时上传并审核新的素材。

单图下线不修改 `ContentSnapshotPayload`。`assetId` 标识同一份不可变文件；一旦任一版本确认该素材有问题并追加下线事件，所有引用它的版本都必须在读取时应用这条全局事实，不能从旧快照重新暴露同一 URL。系统由 `ImageAssetDeliveryProjection` 重新计算每个版本的当前公开交付：

- 必备原封面初始不可交付时直接使用冻结的降级素材；之后原封面下线时追加事件并得到同样投影；
- 活跃版本不得下线必备槽位最后一张可交付素材；非活跃版本仍可为权利或安全原因追加全局下线事实，此时原图与降级图均不可交付的必备槽位标记为 `unavailable`，并失去安全恢复资格；
- 可选封面初始不可交付时直接省略；之后下线时追加事件并省略，不显示空白占位；
- 细节图只交付冻结集合中审核、权利、AI 标识均就绪且未下线的完整子集；初始失败不伪造事件，之后下线才追加事件；
- 新素材或新的降级关系必须复制为新草稿、生成新 `contentVersion` 并重新审核，不能借交付投影改写快照。

单图下线复用内容生命周期的 `lifecycleRevision`、`If-Match` 和 `Idempotency-Key`。下线事件、投影变化、审计记录以及素材公共 URL 的 `purge/deny` 意图在同一 PostgreSQL 事务中保存，无论目标版本当前是否活跃；目标为活跃版本时还要清理内容页面缓存。重复请求返回第一次的结果。初始质量检查失败由冻结元数据直接决定投影，不写虚假下线事件。投影中的素材、方案、下线与审计 ID 均唯一，所有引用属于同一图片组；投影只保存交付状态和事件引用，不复制或覆盖历史图片元数据。

每张图片记录供应商无关的 `generationMethod`。AI 素材必须同时保存声明模型、提示词版本、生成时间和 `reproductionReference`；非 AI 素材的这些字段可以为空。人工检查使用结构化记录，至少覆盖颜色与文案一致、人物与服装完整、权利与身份风险、场景与可模仿性、手机与微信预览、AI 标识合规，并保存审核编号、维护者账号、时间和备注。

## 影响

- 后台上传接口使用 `multipart/form-data`，文件与不带 filename 的普通 JSON 文本字段分开传输；网站运行时不调用生图服务；
- 提交与发布预检确认两个必备槽位都冻结安全降级素材，并确认原图或降级素材至少一者可交付；可选槽位缺失不阻塞发布；
- 内容版本查询可同时显示不可变图片引用和当前追加式交付投影；
- 问题图片下线后，历史快照、校验值、权利记录与人工检查仍可审计；
- 对象存储和 CDN 的实际 `purge/deny` 实现仍由部署任务验收，但不能改变本 ADR 的快照和事件语义。
