# ADR-0015：单人维护版使用八个清晰的内容状态

- 状态：Accepted
- 日期：2026-07-26
- 补充：ADR-0011

## 背景

网页验证版由一名维护者完成编辑、检查、排期和发布，大师在系统外帮助核对。原 PRD 的状态顺序基本可用，但后台必须用普通人能理解的名称展示，并明确大师不通过、修改内容和恢复旧版本时应该怎么处理。

## 决策

后台使用以下八个状态。括号内是程序和接口使用的固定名称：

1. **草稿（`draft`）**：可以修改，尚未形成正式版本；
2. **待大师核对（`in_review`）**：提交后生成不可修改的正式版本，等待大师核对；
3. **需要修改（`changes_requested`）**：大师核对未通过，当前版本不得发布；
4. **可以发布（`approved`）**：大师已经确认，维护者已保存核对凭证并完成上线检查；
5. **已安排上线（`scheduled`）**：等待指定时间自动上线；
6. **已上线（`published`）**：当前对用户展示的活跃版本；
7. **已被新版本替换（`superseded`）**：曾经上线且仍保留在历史中，检查安全后可以恢复；
8. **已下线（`withdrawn`）**：因内容、版权或合规问题停止使用，不能直接重新上线。

允许的主要变化固定为：

```text
草稿
  → 提交并固定
  → 待大师核对
      → 需要修改 → 复制为新草稿
      → 可以发布
          → 已安排上线 → 已上线
          → 立即上线
              → 已被新版本替换
              → 已下线

已被新版本替换 → 恢复旧版本 → 已上线
```

大师核对不通过时，维护者记录问题，当前版本进入“需要修改”，再复制成新草稿修改。不得直接改动已经提交核对的版本。

取消一个尚未生效的排期时，内容回到“可以发布”；排期执行临时失败时仍保持“已安排上线”，系统记录失败并重试，不能错误显示成“已上线”。

恢复旧版本时，旧版本重新成为“已上线”，刚才的活跃版本变成“已被新版本替换”。“已下线”的版本不能直接恢复；确实需要重新使用时，必须复制为新草稿并重新经过大师核对和上线检查。

## 影响

- P0 后台按上述中文名称展示，不要求维护者理解英文状态代码；
- 大师不登录后台，其核对结论和凭证由维护者录入；
- 同一名维护者可以完成全部操作，但系统不能跳过大师核对凭证、完整预览、检查清单和二次确认；
- 每次提交、退回、通过、排期、上线、替换、下线和恢复都记录时间、原因、操作者及对应内容版本；
- PRD 中原有的状态代码可以保留，但多人角色限制和“发布人与创建者必须不同”的规则不再适用于网页验证版。
