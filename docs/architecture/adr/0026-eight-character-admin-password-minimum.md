# ADR-0026：单一维护者密码下限调整为八位

- 状态：Accepted
- 日期：2026-08-03
- 调整：ADR-0022 中的密码长度下限
- 确认记录：GitHub Issue #41；单一维护者明确同意全系统调整

## 背景

ADR-0022 将后台统一简化为账号密码登录，同时保留 16 至 128 个 Unicode code point 的密码长度。单一维护者随后明确要求使用八位本地管理密码，并确认允许把全系统密码下限调整为八位。仅绕过本地数据库或增加开发后门会让登录表单、OpenAPI 与后端行为分叉，因此不采用。

## 决策

后台登录、首次初始化与离线重置统一接受 8 至 128 个 Unicode code point 的密码。OpenAPI、HTTP 正文校验、密码哈希入口、管理端表单和离线命令必须使用同一边界。

继续保留：

- 带自描述参数和随机盐的 scrypt 密码哈希；
- 不存在账号与错误密码的等价哈希工作量和统一错误；
- 请求来源级与账号级 PostgreSQL 持久化限流；
- `HttpOnly`、生产 `Secure`、`SameSite=Strict`、`Path=/admin` 的会话 Cookie；
- 可信同源 `Origin`、会话绑定 CSRF、闲置与绝对期限、全部会话撤销；
- 登录、退出、离线重置、限流、CSRF 拒绝和紧急控制的追加安全审计。

密码仍不写入仓库、环境示例、Issue、URL、浏览器存储或日志。忘记密码仍只能通过服务器上的交互式离线重置处理。

## 影响

- 八位密码可以建立后台会话；七位及以下继续在网页和服务端拒绝；
- 与 16 位下限相比，弱密码的穷举风险增加，维护者需要自行保护后台入口和服务器权限；
- 不增加默认账号、HTTP 初始化、免密入口或仅本地认证分支。

## 未采用方案

- **直接修改数据库绕过长度校验**：会制造无法通过正常登录接口使用的凭据，并破坏契约一致性；
- **仅本地允许八位**：会造成环境行为分叉，重复 ADR-0022 已拒绝的方案；
- **自动写入默认密码**：会形成仓库外仍可预测的共享凭据，不采用。
