# ADR-0011：首版由一人维护并保留大师核对记录

- 状态：Accepted
- 日期：2026-07-26
- 部分替代：ADR-0003 中“编辑者不得审核同一模块”的多人分工要求

## 背景

Five 的网页验证版由一名开发者兼运营者维护，没有条件建立编辑、审核、业务老师和发布人四套后台账号。每日日期、五行和颜色关系仍需要大师帮助核对，已经上线的内容也必须能够下线、恢复和追查历史。

## 决策

首版允许同一名维护者创建、修改、安排上线、立即上线、下线和恢复内容，不要求为不同工作建立多个后台账号。

内容在提交上线检查时生成一份不可修改的版本。上线后需要改字、换图片或调整颜色时，必须复制成新草稿，不能直接改掉用户已经看过的版本。系统始终记录当前对外展示的是哪个版本，并保留每次上线、替换、下线和恢复记录。

日期、干支、五行、五档顺序和颜色关系在上线前必须由大师核对。大师不登录后台；维护者在后台记录核对人称呼、核对时间、结论、备注，以及聊天截图或其他凭证的引用。没有大师核对记录时，系统不允许上线正式内容。

维护者自行检查文案、图片、版权信息、AI 标识和分享海报。点击上线前，后台必须展示完整预览和检查清单，并进行二次确认。图片或版权出现问题时，可以立即下线当前版本；存在以前已经确认安全的版本时，可以恢复该版本。

海报仍从已经上线的内容版本生成，并记录它来自哪个版本。海报生成失败不影响文字和颜色内容正常访问。

## 影响

- 首版后台只需要一个维护者账号和一个完整操作页面，不建设多人审批工作台；
- 后台需要提供草稿、上线前检查、定时上线、立即上线、下线、恢复和历史记录功能；
- 大师核对是上线前必须填写的业务凭证，但不是一个后台用户角色；
- 系统必须保存每个已提交版本的完整内容，不能用新内容覆盖历史版本；
- 所有关键操作都记录时间、操作者、原因和操作前后的版本；
- PRD 中禁止编辑者审核或发布自己内容的规则不再适用于网页验证版，需要同步改为本 ADR 的单人维护方式；
- 团队扩大后是否恢复多人分工，需要重新评审并用新 ADR 替代本决策。
