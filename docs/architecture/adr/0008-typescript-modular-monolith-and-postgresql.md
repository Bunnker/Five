# ADR-0008：后端采用 TypeScript 模块化单体与 PostgreSQL

- 状态：Accepted
- 日期：2026-07-26

## 背景

Five P0 的公共 API、运营后台、内容生命周期、排期发布、海报任务和审计记录共享同一个内容域。发布、撤回、回滚、排期槽替换、幂等记录与任务入队之间存在强事务约束；在首发规模下拆分微服务或同时引入多种持久化基础设施，会增加分布式一致性和运维成本。

## 决策

后端使用 Node.js、TypeScript、NestJS 与 Fastify 适配器建设模块化单体。PostgreSQL 是 P0 唯一的业务事实数据库，负责不可变内容快照、生命周期事件与投影、活跃版本、审核记录、幂等记录、审计记录以及持久化任务和事务发件箱。

HTTP API 与后台 Worker 使用同一代码库和领域模块，但以独立进程运行。涉及状态变化和任务创建的操作必须在同一个 PostgreSQL 事务中写入业务记录与待处理任务；Worker 从持久化任务表领取任务并可安全重试。

P0 不引入 Redis、Kafka 或独立消息队列。只有在性能测试证明 PostgreSQL 成为瓶颈，或出现必须跨服务独立扩缩容、广播和高吞吐消费的实际需求后，才重新评审缓存或消息基础设施。

## 影响

- P0 只有一个后端领域模型和一套数据库事务边界，不按公共端、后台或渠道拆服务；
- `lifecycleRevision`、`scheduleSlotRevision`、`If-Match` 和幂等键仍是 API 契约的一部分，不得只依赖数据库隔离隐式处理并发；
- 排期、发布、撤回、回滚及其任务失效必须在事务内保持原子性；
- OpenAPI 是客户端共享契约的事实源，客户端类型应由契约生成，不直接导入后端内部实体；
- Worker 崩溃或重复执行不得造成重复发布、重复海报或活跃版本漂移；
- 数据库迁移、备份恢复和事务冲突测试属于 P0 技术验收；
- 若未来拆分服务，必须先划定新的领域边界，并通过新 ADR 替代本决策。
