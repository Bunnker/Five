# ADR-0019：公开页面直接显示完整五档算法标签

- 状态：Accepted
- 日期：2026-07-30
- 取代：ADR-0014 的公开档位标签结论
- 补充：ADR-0005

## 背景

ADR-0014 曾要求公开页面把算法中的“较差”和“不利”合并显示为“注意”，希望降低负向表达带来的焦虑。实际页面验证表明，这个合并标签会掩盖五档算法的原始顺序，也容易让用户误以为两组颜色属于同一档，降低结果的可理解性和产品辨识度。

当前公共接口已经分别返回五条档位记录，并在每条记录中同时提供 `tierCode`、`algorithmLabel`、`displayLabel` 和 `displaySection`。因此公开标签可以在不修改接口结构、枚举或五档算法的前提下调整。

## 决策

1. 公开网页、后台公开预览和分享海报直接展示“大吉、次吉、平、较差、不利”五个算法档位。`jiao_cha` 和 `bu_li` 必须分别显示，不能再用一个可见的“注意”标题合并两档。
2. UI 使用每条档位记录的 `algorithmLabel` 作为可见档位名。对 `jiao_cha` 和 `bu_li`，不得把 `displayLabel` 渲染为标题或替代 `algorithmLabel`。
3. OpenAPI 和后端 wire contract 保持不变。现有 `displayLabel: "注意"` 可以继续作为旧客户端兼容和布局分组元数据，`displaySection: "attention"` 也可以继续把后两档放在同一视觉区域；这两个字段都不能改变五条记录的独立顺序和公开标签。
4. 大吉、次吉、平继续提供具体穿法入口；较差和不利分别展示颜色与减少使用说明，不创建负向穿搭详情，也不显示无目标箭头。
5. 平衡建议继续适用于已经穿了较差或不利档颜色的用户：可以用当日大吉色普通配饰做小面积补充。页面使用中性、可执行的表述，不使用红色警报、恐吓文案，也不承诺改变财运、健康或事情结果。
6. 首版仍不推荐吉祥物，不提供商品购买、订单、支付或收款能力。

## 影响

- 前端需要把五条 `tiers` 按 `rank` 展示，并以 `algorithmLabel` 作为可见档位标题；后两档可以共享紧凑容器，但必须保留两个独立标题、颜色组和关系说明；
- 现有 OpenAPI 字段、枚举、生成类型、缓存内容版本和后端持久化不需要迁移；
- `displayLabel` 不再是公开档位标题的事实源，使用它的旧客户端需要在 Issue #36 中改为读取 `algorithmLabel`；
- 后台预览、网页和海报必须使用同一份五档顺序与可见标签；
- ADR-0014 中关于公开合并为“注意”的结论失效，关于普通配饰补充、非承诺表达和不卖货的安全边界由本 ADR 继续确认。
