# 领域文档

本文档规定工程技能在探索和修改本仓库时，应如何读取领域知识与架构决策。

## 开始探索前需要阅读

- 仓库根目录下的 **`CONTEXT.md`**，如果该文件存在。
- **`docs/domain/glossary.md`**，用于了解项目现有的领域词汇。
- **`docs/architecture/adr/`** 中与本次工作相关的架构决策记录。

如果其中某个文件不存在，直接继续工作，不需要报告缺失，也不要提前建议创建。领域建模技能会在概念或决策得到明确结论时创建或补充这些文件。

## 文件结构

本仓库采用单上下文结构：

    /
    ├── CONTEXT.md
    ├── docs/
    │   ├── domain/
    │   │   └── glossary.md
    │   └── architecture/
    │       └── adr/
    └── src/

现有的 `docs/architecture/adr/` 是本仓库唯一的 ADR 存放位置。不要另外创建与之竞争的 `docs/adr/` 目录。

## 使用项目词汇表中的术语

当输出内容涉及领域概念时，例如 Issue 标题、重构方案、假设或测试名称，应使用 `CONTEXT.md` 和 `docs/domain/glossary.md` 中定义的术语。

不要随意使用文档明确避免的同义词。如果所需概念尚未收录，应先重新判断该词是否真的属于本项目；如果确实属于，则将其记录为后续领域建模需要补充的内容。

## 明确指出与 ADR 的冲突

如果拟议工作与现有 ADR 冲突，必须明确指出，不得静默覆盖原有决策：

> _该方案与 ADR-0007 冲突，但值得重新讨论，因为……_
