# Five 傻瓜式运营后台交互规格

> 状态：实现前冻结规格
>
> 日期：2026-08-06；桌面编辑布局于 2026-08-07 经维护者原型确认后修订
>
> 适用范围：Five P0 单一维护者后台
>
> 本文定义待实现行为，不表示相关页面、接口、迁移或测试已经完成。

## 1. 目的

Five 后台的日常用户是一名维护者，而不是内容系统工程师。后台必须让维护者在进入系统后立即回答五个问题：

1. 当前用户端是否正常；
2. 当前用户实际看到了哪个 `servedFortuneDate` 的内容；
3. 两张必备模特图是否齐全；
4. 下一公开内容日是否已在北京时间 13:00 前准备完成，并将在 18:00 正常切换；
5. 如果有问题，下一步应该点哪里修正。

后台应把草稿、不可变版本、排期槽、发布、替换、幂等、缓存失效和审计等复杂规则封装在服务端工作流中。维护者选择日期后，应能在桌面结构化表单中直接修改允许修改的内容，通过真实用户端预览核对结果，并执行与当前日期关系相符的一个主操作。预览点击只提供快捷定位，不能成为开始编辑的前置步骤。

## 2. 非目标

本次重构不做以下事项：

- 不重设计公开用户端的视觉、内容层级和手机交互；
- 不在浏览器中重新计算 `fortuneDate`、日五行、五档、颜色归行或时辰；
- 不用静态 JSON、演示数据或硬编码页面替代 PostgreSQL 中真实已发布内容；
- 不删除内容版本、审计、幂等、并发保护、缓存失效、单图下线或安全恢复能力；
- 不让维护者直接修改已发布快照；
- 不把 GPT Image 2、中转供应商、密钥或费用策略写入领域模块；
- 不在测试中调用付费图片生成接口；
- 不建设完整 DAM、复杂标签管理、素材效果分析或供应商专属素材模型；
- 不增加大师账号、审核队列或多人权限系统；
- 不把可选图片缺失当成异常；
- 不把本地自动测试描述成生产、微信或中国大陆网络验证。

## 3. 事实源与冲突裁决

### 3.1 已确认且不得退化的事实

- 所有业务时间由服务端按 `Asia/Shanghai` 解释；`fortuneDate` 在 23:00 进入下一命理日，跨民用午夜不得再次加一天。
- 公开交付日期 `servedFortuneDate` 独立在 18:00 切换；公开窗口为 `[D - 1 日 18:00, D 日 18:00)`，准备截止保持为生效前五小时，即 13:00。
- 公开页通过真实 `/api/v1/today` 读取当前活跃的已发布版本。
- 自动内容先发布、后检查；首次发布不等待大师依据、人工图片检查和权利材料，但相关记录必须保留。
- 已发布内容订正必须形成新 `contentVersion`，原子替换 `ActiveVersion`；同一 `fortuneDate` 只能有一个活跃版本。
- 每日图片口径是两个必备封面槽位和最多一个可选封面槽位。细节图、候选图和降级图不计入 2+1。
- 单图下线不改不可变快照。必备图切换到安全降级素材，可选图省略；不能让正确日期和文字内容随问题图片一起下线。
- 发布、替换、下线和恢复必须保留 `If-Match`、revision、`Idempotency-Key`、审计及缓存清理语义。

### 3.2 本规格发现的冲突

| 冲突 | 当前证据 | 本规格裁决 | 编码前动作 |
|---|---|---|---|
| 后台默认入口 | PRD 16.1 与 ADR-0025 仍写“月日历”；本次产品要求一级入口为“今日” | 日常默认入口改为“今日”，月日历保留为第二入口 | 更新 PRD 并新增或补充 Accepted ADR |
| 草稿提交状态 | ADR-0024 和当前 PRD 要求默认进入 `approved`；OpenAPI 的 submit 成功说明仍写 `in_review` | 默认 `draft → approved`，`in_review` 仅兼容历史数据 | 先修正 OpenAPI、示例和契约测试 |
| 发布前图片门槛 | ADR-0021/旧契约把人工检查与安全降级视为强门槛；ADR-0024 取消本地首次发布的人工作业门槛 | 至少两张必备候选仍是首次公开内容的最低输入；人工检查等转为发布后追溯，不得破坏单图下线安全规则 | 在 PRD/ADR 中明确“首次发布输入”与“发布后检查”的边界 |
| 18:00 规则 | ADR-0027 曾把 18:00 定义为准备截止、23:00 定义为公开生效 | 按 ADR-0028：13:00 为准备截止，18:00 切换 `servedFortuneDate` 和用户侧内容；23:00 命理规则不变 | OpenAPI、后端、Worker、网页和测试统一改用公开交付上下文 |
| 算法只读 | 当前模块 PATCH 可提交完整 `calendar_algorithm`；当前可视化编辑器也会回传完整模块 | 普通订正只能写白名单展示字段；算法结果只读 | 新增语义订正契约，普通 UI 不调用完整算法模块 PATCH |
| 图片槽位 | 生产任务有 `imageSlot`，但 `draft_image_candidates` 未保存槽位，冻结时按上传顺序映射 | 候选必须持久化槽位并按槽位冻结，禁止按完成/上传顺序推断 | 增加迁移、回填策略与槽位一致性测试 |
| 自动文字来源 | `DeterministicDraftGenerator` 仍调用 `createDemoDailyContent` | 自动内容必须改为正式、版本化结构化生成器；确定性算法继续来自日历领域模块 | 在真实链路验收前不得宣称“已去除 demo” |

若上述文档尚未完成更新，本文可以指导实现准备，但不得以本文单独覆盖 PRD、Accepted ADR 或 OpenAPI 的事实源地位。

## 4. 信息架构

### 4.1 一级导航

普通后台一级导航固定为：

1. **今日**：默认入口，回答当前用户内容是否正常和下一公开内容日是否准备好；
2. **日历**：按月查看每日真实运营状态；
3. **异常**：只显示维护者现在能处理的问题。

以下能力放入右上角“更多”菜单，不占一级导航：

- 安全设置；
- 恢复旧版本；
- 审计记录；
- 高级配置；
- 紧急控制。

登录页只显示账号、密码和登录按钮。离线密码重置与安全恢复不进入日常登录流程。

### 4.2 四个页面

| 页面 | 路由建议 | 目的 |
|---|---|---|
| 今日 | `/admin` | 查看当前线上效果、下一公开内容日准备状态与当前异常 |
| 日历 | `/admin/calendar` | 按月查看每个命理日的内容、发布与必备图状态 |
| 异常 | `/admin/issues` | 集中处理当前可行动问题 |
| 日期详情 | `/admin/calendar/{fortuneDate}` | 通过桌面结构化表单直接订正，并用真实用户端预览核对结果 |

日期详情不是第四个一级导航项。它必须提供 `日历 > YYYY年M月 > M月D日` 面包屑，以及返回“今日”或“日历”的明确入口。

## 5. 统一后台读模型

### 5.1 原则

今日、日历、异常和日期详情不得各自在浏览器中拼接 production、draft、version 和 image-set 后推导不同结论。后端必须提供一个 `AdminOperationsReadModel`，在一致的服务端时间和数据库视图上生成四类响应：

- `AdminOperationsOverview`；
- `AdminCalendarMonth`；
- `AdminDayDetail`；
- `AdminActionableIssueList`。

所有响应必须包含同一次生成的 `requestContext` 与 `servedFortuneDate`，或引用同一次服务端公开交付上下文。页面可以持有内部 ID、revision 和 ETag 以执行安全写操作，但不得把它们作为普通维护者可见文案。

### 5.2 日级摘要

`AdminDaySummary` 至少包含：

- `fortuneDate`；
- 与当前公开交付日的关系：`current | next | future | past`，只按 `servedFortuneDate` 判断；
- `effectiveFrom`、`effectiveTo`、`prepareBy`；
- 只读的日五行与大吉主色；
- 运营状态；
- 当前活跃版本、排期版本或可编辑工作副本的内部引用；
- `lifecycleRevision`、`scheduleSlotRevision`、`draftRevision` 等并发数据；
- 必备模特图完成度；
- 必备公开交付安全度；
- 可选图状态；
- 更新时间；
- 可行动异常摘要。

运营状态是读模型，不新增内容生命周期状态。建议固定为：

- `published_healthy`：当前已发布且公开交付正常；
- `published_degraded`：当前已发布，但一张必备模特图正在使用降级素材；
- `scheduled_ready`：未来版本已完整冻结并排期到正确 `effectiveFrom`；
- `preparing`：截止时间前仍在生成或等待排期；
- `overdue`：已到 `prepareBy` 仍未就绪；
- `generation_failed`：必备文字或图片生成失败；
- `publication_failed`：应发布但发布任务失败；
- `missing`：没有可形成预览的内容；
- `invariant_broken`：活跃版本、排期槽或图片投影违反领域不变量。

## 6. 今日页面

### 6.1 数据来源

- `GET /admin/api/v1/operations/overview`；
- “当前·用户正在看到”必须使用 `servedFortuneDate` 的 `ActiveVersion` 和当前图片交付投影，通过与公开 `/today` 相同的投影器构建预览；
- “下一日”使用 `servedFortuneDate + 1 天` 的有效排期版本；若尚无排期，才依次回退到 approved 版本和自动生成工作副本，并明确标记为尚未上线；
- 系统健康提示来自运营读模型，不显示 `/health` 原始响应、日志或内部错误对象。

### 6.2 页面结构

页面首屏按以下顺序展示：

1. 总状态：`运行正常`、`有 N 个问题需要处理` 或 `用户端内容不可用`；
2. **当前·用户正在看到**卡片；
3. **下一日·准备中/已就绪**卡片；
4. 当前可行动异常摘要。

当前和下一日卡片必须同时显示明确日期、`servedFortuneDate` 关系标签和不同的状态色。禁止只写“今日内容”而不显示实际日期；18:00 换位时两张卡必须一起刷新。

### 6.3 页面状态与操作

| 区域状态 | 可见信息 | 主操作 | 次操作 |
|---|---|---|---|
| 当前正常 | 已发布、更新时间、必备图 `2/2`、真实预览 | 修改当前内容 | 查看公开页 |
| 当前降级 | 用户仍可访问、必备模特图 `1/2`、降级说明 | 更换问题图片 | 查看当前降级 |
| 当前无内容 | 18:00 已切换但用户端没有可用内容 | 准备并发布当前日 | 进入异常 |
| 下一日就绪 | 日期、`13:00 前已准备`、`18:00 生效`、必备图 `2/2`、预览 | 查看下一日 | 重新生成图片 |
| 下一日准备中 | 当前进度、prepareBy、必备图 x/2 | 查看准备进度 | 手动补图 |
| 下一日逾期 | 已超过 13:00、未就绪原因 | 立即处理下一日 | 查看异常 |

“系统正常”只有在当前公开内容可读取、活跃版本唯一且两个必备公开槽位安全时显示。可选图缺失不改变该结论。

## 7. 月日历页面

### 7.1 数据来源

- `GET /admin/api/v1/operations/calendar?month=YYYY-MM`；
- 月份、当前公开交付日标记和日期关系由服务端响应决定；
- 前端只负责网格布局，不根据本地 `Date` 推导当前业务日或发布状态。

### 7.2 日期格

每个日期格只展示：

- 公历日号；
- 日五行或大吉主色；
- `已发布 / 已就绪 / 准备中 / 异常 / 未准备`之一；
- 必备模特图 `x/2`；
- 可选图有无的弱提示，可省略文字但不得计入错误色。

日期格不显示：

- 模特图缩略图；
- 草稿 ID 或版本 ID；
- `/3` 总图片进度；
- JSON；
- Worker 状态代码；
- 审核队列名称。

点击任一日期格进入日期详情。键盘焦点、`aria-label` 和点击区域必须可用；主要点击区域不小于 44×44px。

### 7.3 页面状态与操作

- 加载：显示稳定月历骨架，不用旧月份数据冒充新月份；
- 空月份：显示“这个月尚无内容”，提供“生成未来内容”入口；
- 部分失败：已经成功读取的日期仍可查看，页顶显示可重试提示；
- 主操作：点击日期；
- 次操作：上月、下月、回到当前公开交付月。

## 8. 异常页面

### 8.1 数据来源

- `GET /admin/api/v1/operations/issues`；
- 问题由内容、排期、图片生产、发布任务和交付投影实时派生；
- P0 不新建可编辑的“工单状态机”。问题在根因修复后自动消失，历史行为通过审计记录追溯。

### 8.2 允许出现的问题

- `CURRENT_CONTENT_UNAVAILABLE`：当前 `servedFortuneDate` 没有已发布内容，包括 18:00 切换后新日内容缺失；
- `NEXT_DAY_OVERDUE`：13:00 后下一公开内容日仍未就绪；
- `REQUIRED_IMAGE_MISSING`：必备模特图不足两张；
- `REQUIRED_IMAGE_GENERATION_FAILED`：必备槽位自动生成失败；
- `CONTENT_GENERATION_FAILED`：文字或结构化内容自动生成失败；
- `AUTO_PUBLICATION_FAILED`：到达生效时间后自动发布失败；
- `ACTIVE_VERSION_INCONSISTENT`：活跃版本不唯一或指针异常；
- `REQUIRED_IMAGE_DEGRADED`：必备模特图已切换到安全降级素材；
- `SAFE_FALLBACK_EXHAUSTED`：必备槽位没有安全交付内容。

可选图片缺失或生成失败、普通技术告警、日志噪声以及不影响用户的重试不得进入异常中心。

### 8.3 问题卡片

每张问题卡片只包含：

- 人类语言标题；
- 受影响日期；
- 用户现在会看到什么；
- 系统已采取的降级；
- 一个直接操作按钮；
- 首次发现与最近更新时间。

普通页面不得显示堆栈、SQL、错误对象、Worker 日志或供应商响应。高级信息只在“更多 > 审计记录/高级配置”按权限查看。

## 9. 日期详情与真实预览

### 9.1 数据来源

- `GET /admin/api/v1/operations/days/{fortuneDate}`；
- 已发布日期使用当前不可变快照及交付投影；
- 已排期日期使用排期版本；
- 尚未冻结的日期使用可编辑工作副本；
- 预览必须通过共享 `DailyExperienceView` 构建。公开页和后台不得各自维护一套组件结构或字段转换。

### 9.2 页面结构

桌面布局固定为：

1. 全宽面包屑与日期状态头，显示具体日期、日期关系、运营状态、13:00 准备截止、18:00 生效时间、必备图 `x/2` 与可选图独立状态；
2. 左侧约 65% 的结构化编辑区，建议在 1440px 视口下保持约 880 至 900px；
3. 右侧约 30% 的粘性结果预览区，内部真实用户端渲染保持约 375px，但不使用厚重手机外壳；
4. 底部粘性操作栏，集中显示未保存变更、字段校验、必备图状态和日期相关的唯一主操作。

结构化编辑区是唯一正式编辑面，按以下顺序直接展示：

1. `算法结果 · 只读`：日期、时辰、日五行、五档顺序和颜色的紧凑摘要；
2. `五档说明`：五档名称、颜色与顺序只读，每档说明文案直接编辑；
3. `穿搭内容`：单色、双色、三色方案的标题和说明；
4. `配饰与分享`：配饰建议、参考声明中允许修改的展示文案和多行分享文案；
5. `图片管理`：主方案、备选方案和可选图三张卡片，其中前两张明确标记为必备，可选图明确标记为不影响发布。

结果预览复用公开页面的日期区、五档卡片、穿搭区、图片区和声明组件。后台可以增加选中轮廓，但不得更改公开内容的排序、色点、档位名称或手机宽度表现。输入变更应即时更新工作副本预览；预览区可以独立滚动、折叠或在新窗口打开，不能压窄正式输入框。

### 9.3 结构化编辑与预览定位

维护者无需先点击预览即可编辑任何允许修改的字段。字段聚焦时，预览可以轻量高亮对应内容；点击预览对象时，页面可以滚动并聚焦对应表单字段。该双向定位是效率增强，不得作为编辑依赖，也不得在切换定位时重置尚未保存的输入。

| 编辑分组 | 正式编辑控件 | 预览定位对象 | 写入边界 |
|---|---|---|---|
| 算法摘要 | 无输入控件，仅提供“报告算法异常” | 日期、干支、日五行、档位顺序与颜色 | 全部只读 |
| 五档说明 | 五个始终可见的说明 textarea | 对应档位解释 | 只写 explanation |
| 平衡与配饰 | 描述和普通配饰示例 | 平衡建议区域 | 不得改 preferredTierCode |
| 穿搭内容 | 单色、双色、三色的标题与说明 | 对应穿搭卡片 | 不得改公式 ID、tierCode 或 colorCodes |
| 分享与声明 | 支持换行的展示文案输入框 | 分享与声明区域 | 不得改来源版本或推导步骤 |
| 主方案图片 | 当前图与槽位内操作 | 必备主图 | 固定槽位 |
| 备选方案图片 | 当前图与槽位内操作 | 必备备选图 | 固定槽位 |
| 可选图 | 添加、替换或下线操作 | 可选图 | 缺失允许且不报错 |

完整 JSON 不出现在普通日期详情中。不得引入区块排序、页面搭建、拖拽布局或第二套公开展示模型。

## 10. 算法只读边界

普通订正界面永远不能写入：

- `fortuneDate`、`civilDate`、`effectiveFrom`、`effectiveTo`、`dayBoundary`；
- 干支、日支、日五行、时辰及跨日状态；
- 五档 `rank`、`tierCode`、`algorithmLabel`、`element`、`colors` 和顺序；
- 颜色归行；
- `calendarDataVersion`、`calendarRuleVersion`、`algorithmVersion`；
- 穿搭公式中的档位与颜色代码；
- 任何已有 `contentVersion`。

普通字段订正请求必须使用语义化白名单，服务端从当前工作副本读取并只替换允许字段。不得要求前端回传完整 `CalendarAlgorithmModule` 后依靠 UI 自觉不改算法。

如果维护者认为算法错误，抽屉只显示“进入规则订正”。规则订正属于高级流程，必须重新运行 366 日黄金答案、边界样例和文档决策，不得单日覆盖。

## 11. 当前、下一日、未来与过去

| 日期关系 | 选择依据 | 预览来源 | 主操作 | 生效语义 |
|---|---|---|---|---|
| 当前 | 等于服务端 `servedFortuneDate` | 当前 ActiveVersion | 保存并立即替换 | 新版本原子替换当前活跃版本 |
| 下一日 | 服务端在 `servedFortuneDate` 上加一日 | 正确排期版本，缺失时回退工作副本 | 保存并在指定 18:00 生效 | 排期到该日 `effectiveFrom` |
| 未来 | 大于下一日 | 排期版本或工作副本 | 保存并在指定 18:00 生效 | 原子占用/替换该日排期槽 |
| 过去 | 小于当前 `servedFortuneDate` | 当前历史公开版本/最近版本 | 默认只读 | 修改历史分享页另走高级流程 |

未来日期按钮必须显示具体时间，例如“保存并在 8月6日 18:00 生效”，不能只写含糊的“定时发布”。

## 12. 12:59、13:00、17:59、18:00 与 23:00 时间模型

### 12.1 统一计算

对命理日 `D`：

- `effectiveFrom(D)` 等于北京时间 `D - 1` 的 18:00；
- `prepareBy(D) = effectiveFrom(D) - 5 小时`，即北京时间 `D - 1` 的 13:00；
- `effectiveTo(D)` 等于北京时间 `D` 的 18:00；
- `servedFortuneDate` 在 18:00 切换，`requestContext.fortuneDate` 仍在 23:00 切换；
- 以上值只由服务端领域规则生成。

### 12.2 下一日就绪定义

下一日只有同时满足以下条件才显示“已就绪”：

1. 已形成不可变版本；
2. 版本状态为 `scheduled`，且排期时间严格等于 `effectiveFrom`；
3. 必备模特图为 `2/2`；
4. 两个必备公开槽位都有安全可交付内容；
5. 可构建完整用户端展示模型；
6. 没有未解决的必备生成或排期失败。

可选图缺失、人工检查未补充、大师依据未补充不阻止“已就绪”，但可以在高级追溯信息中显示。

### 12.3 边界行为

| 北京时间 | 期望行为 |
|---|---|
| 12:59:59 | 下一日未完成仍显示“准备中”，除非已有明确生成失败，否则不产生逾期异常 |
| 13:00:00 | 下一日仍未满足就绪条件时生成 `NEXT_DAY_OVERDUE`，当前公开内容不变 |
| 17:59:59 | 用户仍读当前 `servedFortuneDate` 的活跃版本；缓存不得跨过下一秒 |
| 18:00:00 | `servedFortuneDate` 前进一次；排期版本原子成为新 ActiveVersion，后台 current/next 同时换位；缺少新日内容时 fail closed |
| 22:59:59 | `servedFortuneDate` 已是下一日，命理 `fortuneDate` 尚未前进，两者有意不同 |
| 23:00:00 | 命理 `fortuneDate` 前进一次；只刷新命理上下文和时辰，不重复发布或换位 |
| 23:59:59 → 00:00:00 | 两个日期都保持不变，不再次加一天 |

后台响应应返回 `servedFortuneDate` 与 `nextOperationalBoundaryAt`。后者只表示下一公开内容日的 13:00 `prepareBy` 或 18:00 `public effectiveFrom`，不包含 23:00 命理换日、时辰边界或民用午夜；前端可以据此刷新读模型，但不能自行推进日期或推断业务状态。

## 13. 图片口径与维护

### 13.1 两个独立指标

后台必须区分：

- **必备模特图完成度**：原始模特封面是否齐全，显示 `x/2`；
- **必备公开交付安全度**：原图或冻结降级素材是否可交付，内部口径也是 `x/2`。

若一张必备模特图下线但安全降级卡已接管：

- 用户端继续展示正确日期和文字；
- 后台显示“必备模特图 1/2”；
- 同时显示“公开交付安全 2/2”；
- 异常中心出现可行动的“必备图正在降级”问题。

### 13.2 槽位规则

- `required_primary`：必备主图；
- `required_alternative`：必备备选图；
- `optional`：最多一张可选图；
- 候选、生成任务、上传关联、冻结快照和交付投影必须始终携带同一 `imageSlot`；
- 同一素材不得同时计入两个必备模特图；
- 可选图缺失或省略时不显示空白占位、不进入异常、不降低日期健康状态。

### 13.3 图片抽屉操作

每个槽位提供：

- 重新生成；
- 从已有搭配库选择；
- 手动上传；
- 单图下线；
- 查看当前状态。

重新生成、搭配库选择和上传不会修改在线快照。它们写入从基线版本复制的工作副本，只有执行页面主操作后才形成新版本并替换或排期。

单图下线继续使用现有追加式交付投影：

- 必备图切安全降级；无安全降级时服务端拒绝下线并给出可理解错误；
- 可选图直接省略；
- 活跃内容受影响时写入缓存清理意图；
- 相同幂等键的重试返回第一次结果。

搭配库在本次只做现有安全素材的只读选择器。可以按颜色组合、场景和人群筛选，但不建设标签管理、批量管理和效果分析。

## 14. 语义订正与现有生命周期映射

### 14.1 工作副本

打开日期详情不得产生写操作。第一次修改文案、重生成、选择素材或上传时，服务端才创建或复用该日期的订正工作副本：

- 当前 `servedFortuneDate` 从当前 ActiveVersion 复制；
- 未来从当前排期版本复制；没有排期时从最新 approved 版本或自动草稿开始；
- 工作副本继续使用 `draftRevision` 和 ETag；
- UI 可以持有 `draftId`，但不显示给维护者。

### 14.2 字段订正

抽屉保存调用语义字段 PATCH。服务端执行：

1. 校验字段在白名单中；
2. 校验 `If-Match`；
3. 读取当前完整模块；
4. 只替换允许字段；
5. 增加 `draftRevision`；
6. 返回新 ETag 和更新后的预览模型。

发生 `412 REVISION_MISMATCH` 时不得覆盖服务端内容。界面显示“页面内容已更新，请重新载入后继续”，保留尚未提交的输入供维护者复制。

### 14.3 保存并立即替换

当前 `servedFortuneDate` 的主操作必须由服务端 `DayCorrectionWorkflow` 执行，不由前端串联多个写请求。工作流必须复用现有事务化 submit 与 release 接缝，并以同一外部幂等键派生固定子键：

1. 校验基线 ActiveVersion 和 lifecycle revision；
2. 冻结工作副本，生成新 `contentVersion`，默认进入 `approved`；
3. 原子把旧 ActiveVersion 变为 `superseded`、新版本变为 `published`；
4. 保证同日只有一个 ActiveVersion；
5. 追加操作者、时间、原因、前后版本和 request ID；
6. 写入公共内容缓存清理及相关任务失效意图；
7. 用幂等键保证网络重试不重复生成版本或发布；若 submit 已完成而 release 暂时失败，保留安全的 `approved` 版本，重试从同一 `contentVersion` 继续，界面不得声称已经替换成功。

主按钮文案固定为“保存并立即替换”。成功提示使用“已生成新版本并替换当前用户内容”，不显示内部版本号。

### 14.4 保存并在 18:00 生效

下一日与未来日期的主操作由同一工作流执行：

1. 冻结工作副本为 `approved` 新版本；
2. 校验 `effectiveFrom` 来自服务端日历规则；
3. 原子替换同日排期槽：旧 scheduled 版本回到 `approved`，新版本进入 `scheduled`；
4. 同时递增 `lifecycleRevision` 和 `scheduleSlotRevision`；
5. 终止被替换版本的旧排期任务；
6. 记录审计并保持幂等。

主按钮显示具体生效时间。到达 `effectiveFrom` 后，发布 Worker 继续使用现有排期 fencing 规则，不能因重试产生重复发布或活跃版本漂移。

### 14.5 恢复与整版下线

- “恢复上一安全版本”只放在“更多”；
- 目标必须是同一 `fortuneDate`、曾经发布、当前为 `superseded` 且仍安全的版本；
- `withdrawn` 不能直接恢复或重新发布；
- 整版下线属于高风险操作，继续要求原因、精确确认、revision 与幂等键；
- 普通文案或单图问题优先走新版本替换或单图下线，不应整版下线。

## 15. 错误与降级

| 场景 | 用户端 | 后台呈现 | 直接操作 |
|---|---|---|---|
| 当前公开交付日无活跃内容 | 返回既有 `CONTENT_NOT_READY` 安全状态 | 红色异常，说明“用户现在看不到当前日期建议” | 准备并发布当前日 |
| 必备模特图缺一张但有降级 | 继续交付降级卡 | `1/2`，公开交付仍安全 | 更换问题图片 |
| 必备图无安全降级 | 阻止危险下线或进入安全不可用状态 | 最高级异常 | 上传安全替代图 |
| 可选图缺失/失败 | 省略该卡片 | 普通状态，不进入异常 | 可选地重新生成 |
| 下一日 13:00 前未完成 | 不影响当前用户 | “准备中” | 查看进度/补图 |
| 下一日 13:00 后未完成 | 18:00 前不影响当前用户，但已有切换风险 | 逾期异常 | 立即处理下一日 |
| 18:00 到点仍无新日内容 | fail closed，不继续展示越过窗口的旧内容 | 当前内容不可用最高级异常 | 立即准备并发布当前日 |
| 自动发布失败 | 保持旧安全内容或现有安全响应 | 明确用户影响与失败日期 | 安全重试发布 |
| 并发冲突 | 不改变线上状态 | 提示刷新，不自动覆盖 | 重新载入 |
| 图片供应商不可用 | 用户访问绝不触发生图 | 必备任务失败才进入异常 | 重试/上传/搭配库 |

所有普通错误文案必须由稳定产品错误码映射，不直接展示异常消息、供应商正文或数据库错误。

## 16. OpenAPI 增量

接口变更必须先写入 `docs/api/openapi.yaml`、示例与契约检查，再生成 TypeScript 类型并修改调用方。

### 16.1 新增只读接口

- `GET /admin/api/v1/operations/overview`
  - 返回 `requestContext`、`servedFortuneDate`、current、next、健康摘要与当前问题数量；
- `GET /admin/api/v1/operations/calendar?month=YYYY-MM`
  - 返回 42 格月历窗口或明确的月内日期集合，以及每日日级摘要；
- `GET /admin/api/v1/operations/issues`
  - 返回可行动问题，不返回堆栈；
- `GET /admin/api/v1/operations/days/{fortuneDate}`
  - 返回日级摘要、共享预览模型、可编辑字段能力和内部并发数据。

### 16.2 新增语义订正接口

- `POST /admin/api/v1/operations/days/{fortuneDate}/corrections`
  - 第一次修改时创建或复用工作副本；
- `PATCH /admin/api/v1/operations/corrections/{correctionId}`
  - 只接受白名单语义命令和值，要求 `If-Match`；
- `POST /admin/api/v1/operations/corrections/{correctionId}/apply`
  - 要求 `If-Match`、`Idempotency-Key`、expected active version 与 revision；调用方不得传保存模式，服务端用同一次公开交付上下文判断当前日立即替换或未来日按固定 `effectiveFrom` 排期；
- `POST /admin/api/v1/operations/corrections/{correctionId}/image-slots/{imageSlot}/regenerate`；
- `POST /admin/api/v1/operations/corrections/{correctionId}/image-slots/{imageSlot}/select-existing`；
- `POST /admin/api/v1/operations/corrections/{correctionId}/image-slots/{imageSlot}/upload`。

现有低层草稿、版本、发布、排期、下线和恢复接口保留，供高级页面和兼容调用方使用。普通后台只调用运营读模型和语义工作流。

### 16.3 新增或修正的主要 Schema

- `AdminOperationsOverview`；
- `AdminDaySummary`；
- `AdminCalendarMonth`；
- `AdminDayDetail`；
- `AdminActionableIssue`；
- `RequiredImageReadiness`，分开 `modelReadyCount` 与 `deliverySafeCount`；
- `OptionalImageStatus`；
- `DayCorrectionFieldPatch`；
- `ApplyDayCorrectionRequest/Result`；
- `DailyContentProduction` 增加逐槽位状态，不能只返回 0..3 总数；
- submit 成功说明与示例从默认 `in_review` 修正为 `approved`。

### 16.4 错误码增量

至少需要稳定映射：

- `CORRECTION_FIELD_NOT_EDITABLE`；
- `CORRECTION_BASE_VERSION_CHANGED`；
- `DAY_CORRECTION_NOT_READY`；
- `IMAGE_SLOT_MISMATCH`；
- `REQUIRED_IMAGE_NOT_READY`；
- `SCHEDULE_SLOT_CHANGED`。

不得把普通领域分支只表示成 500。

### 18.1 关键验收用例

1. 12:59 下一日未完成仅显示准备中，13:00 起进入逾期异常；
2. 17:59→18:00 后公开内容与后台 current/next 按服务端 `servedFortuneDate` 前进；缺少新日内容时 fail closed；
3. 22:59→23:00 只推进命理 `fortuneDate`，不重复发布；23:59→00:00 不重复跨日；
4. 当前日文案订正后产生新版本，旧版进入 `superseded`；
5. 未来日期订正后只在正确 `effectiveFrom` 生效；
6. 任意重试后同日始终只有一个 ActiveVersion；
7. optional 缺失不显示错误、不进入异常；
8. 两个图片任务逆序完成仍映射到正确必备槽位；

14. 所有自动测试确认没有调用真实图片供应商。

## 19. 回退策略

- 新运营读接口是新增接口，旧低层接口保留，因此 UI 可以按页面回退，不需要破坏数据模型；
- `image_slot` 迁移上线前必须在一次性旧版本数据库副本验证回填。自动候选优先依据生产任务的 `image_slot + completed_asset_id` 精确回填；无法确定槽位的历史候选保持 `null`，只能待人工选择；
- 语义订正失败时工作副本保留，线上 ActiveVersion 不变化；
- release 事务失败不能改变线上 ActiveVersion；允许留下同一幂等工作流可继续的安全 `approved` 版本，但 UI 只能显示“尚未生效”，重试不得创建第二版本；
- 前端回退不能重新启用客户端日期算法或 demo 数据；
- 回退代码不等于回退数据库事实。已写入的审计、版本与下线事件继续保留。

## 21. Issue-ready 摘要

### 标题

重构 Five 后台为“今日、日历、异常”驱动的傻瓜式运营控制台

### 背景

当前后台以草稿、版本、JSON、生产队列和生命周期操作为中心。单一维护者无法快速确认今天用户看到什么、明天是否准备好，也难以通过真实用户端预览直接订正文案和图片。自动生产链路还存在 demo 文案来源和图片候选按完成顺序误配槽位的风险。

### 目标

新增一致的服务端运营读模型和语义订正工作流，把普通导航收束为今日、日历、异常。日期详情以桌面结构化表单为唯一正式编辑面，并在右侧复用真实 375px 用户端展示模型进行实时核对；预览点击仅用于快捷定位。当前 `servedFortuneDate` 保存后新版本立即替换，未来日期保存后在正确 18:00 生效；准备截止为 13:00，23:00 命理规则不变。

### 必须交付

- overview、calendar、issues、day-detail 四个服务端读模型；
- required `2/2` 与 optional 分离的图片口径；
- 持久化图片候选槽位并修复顺序误配；
- 白名单语义订正与幂等、可恢复的 apply 工作流；
- 今日、日历、异常、日期详情四页；
- 共享用户端/后台预览组件；
- OpenAPI、迁移、单元、集成、RTL、E2E 和 375px 回归测试；
- 去除自动内容链路对 demo 生成器的依赖。

### 不可破坏

- 23:00 fortuneDate 切换与 00:00 不重复跨日；
- 18:00 servedFortuneDate 与用户内容切换，缺内容时 fail closed；
- `/today` 真实 ActiveVersion；
- 单一活跃版本、不可变快照、审计、revision、幂等与缓存清理；
- 单图下线和安全降级；
- 当前用户端视觉与完整五档；
- 测试不调用付费生图接口。

### 完成判定

本文第 18 节全部适用测试通过，普通后台不暴露 JSON/内部 ID/工程日志，current 与 next 不混淆，可选图缺失不报错，当前与未来的保存分别满足立即替换和 18:00 生效语义，23:00 不重复发布，并且没有未经授权的提交、推送、部署或生产数据操作。
