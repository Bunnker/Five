## 1. 本轮产品决定

此前“375px 手机预览必须作为日期详情主编辑器”的约束已经撤销。维护者已明确反馈该模式修改内容不方便，并确认新的高保真原型方向。

本轮冻结为：

- 日期详情采用桌面优先的“结构化表单主导 + 右侧实时用户端预览”；
- 左侧结构化表单是唯一正式编辑面；
- 右侧 375px 用户端预览只负责核对结果、定位字段和打开完整页面；
- 维护者无需先点击预览即可修改全部允许字段；
- 点击预览或聚焦字段不能清空其他尚未保存的输入；
- 公开用户端视觉和内容层级不重设计。

批准的布局参考位于上下文包：

- `references/approved-admin-desktop-prototype.png`；
- `references/current-admin-date-detail.png`；
- `references/current-public-page.png`。

原型只冻结信息架构、比例和交互方向，不是像素级事实源。实现必须复用仓库现有视觉变量、基础组件和真实展示模型。

## 2. Phase 1 实施目标

### 2.1 日期详情

在 1440px 桌面视口下：

- 顶部全宽显示面包屑、具体日期、日期关系、运营状态、13:00 准备截止、18:00 生效时间、必备图 `x/2` 和可选图独立状态；
- 主体约 65/35 分栏：左侧约 880 至 900px 正式编辑区，右侧约 400 至 420px 粘性预览区；
- 左侧直接展示以下分组，不再使用“选择要修改的内容”按钮墙：
  1. 算法结果只读摘要；
  2. 五档说明；
  3. 单色、双色、三色穿搭标题与说明；
  4. 配饰建议、允许修改的展示声明和多行分享文案；
  5. 主方案、备选方案和可选图三张图片卡片；
- 算法摘要中的 `fortuneDate`、日期与时辰、日五行、五档名称、顺序和颜色没有输入控件，也没有可编辑 hover 状态；
- 两张必备图与一张可选图独立表达。可选图缺失显示“不影响发布”，不得使用错误色；
- 每张图片卡片继续提供现有的重新生成、搭配库选择、上传和单图下线能力；
- 右侧预览复用真实 `DailyExperienceView` 或同一展示模型，支持独立滚动、折叠和打开完整页面；
- 字段聚焦时预览可高亮对应内容，点击预览时可定位字段，但预览不是编辑前置条件；
- 底部粘性操作栏显示变更数量、校验状态和必备图状态；当前公开日使用“保存并立即替换”，未来日期显示具体日期的“保存并于 M月D日 18:00 生效”。

### 2.2 今日页

- 不再用两部长手机页面主导首屏；
- 用“当前公开”和“下一份内容”两张清楚的状态卡回答日期、状态、必备图、可选图、准备截止和生效时间；
- 右侧或次要区域保留尺寸克制的结果预览，可在当前和下一份之间切换；
- 当前问题只显示可行动摘要；没有问题时明确显示无需人工处理；
- 直接入口为“查看日期详情”和“查看并订正”。

### 2.3 用户端信息简化

大师针对真实用户端提出以下反馈，本轮只做不改变算法和数据的最小展示调整：

- 隐藏五档卡片右上角当前由 `tier.relationText` 渲染的“土生金”等专业生克关系短标签；
- 放大同一区域的 `tier.elementLabel`（“金、木、水、火、土”），使用户先看懂该档对应的五行；
- 五档颜色、顺序、档位名称和穿搭建议继续完整展示；
- 不删除后端算法字段，不修改日历推导、五档计算或 OpenAPI；仅从普通用户首屏弱化或隐藏专业解释；
- 后台算法只读摘要仍可保留必要的内部核对信息，但普通维护者不能修改。

红线反馈对应当前 `DecisionColorCard` 中的 `tier.relationText`，不得通过字符串匹配删除数据，也不要顺带改写 `tier.explanation` 正文。优先在共享公开展示组件中调整可见层级，并补充五档公开页面与后台预览回归测试。

### 2.4 响应式退化

- `>= 1280px`：编辑区和预览并排，预览 sticky；
- `1024px–1279px`：表单占主要宽度，预览默认收为右侧抽屉或覆盖层，不得压窄输入框；
- `375px` 管理端：单列结构化表单，预览全屏打开，不能出现“手机框套手机页面”；图片纵向排列，底部保存操作 sticky，全页无横向滚动，主要操作区域不小于 44×44px。

## 3. 必须保持的系统边界

- 公开内容在北京时间 18:00 切换；13:00 是下一公开日准备截止；23:00 只推进命理 `fortuneDate` 与时辰，不能再次切公开内容；
- `/today` 继续读取 PostgreSQL 中真实 ActiveVersion，不得引入 demo 或硬编码数据；
- 当前公开日订正创建新版本并立即原子替换；未来日期订正在对应公开窗口 18:00 生效；
- 不可变版本、单一 ActiveVersion、revision、If-Match、幂等、审计、缓存失效、单图下线与安全恢复全部保留；
- 普通页面不得出现 JSON、草稿 ID、版本 ID、revision 数字、审核批准队列或工程日志；
- 图片口径保持两张必备图加最多一张可选图；
- 自动测试不得调用付费生图接口；
- 不得提交、推送、部署、迁移真实数据库或操作真实用户数据。

## 4. 实施边界

优先使用当前已经存在的：

- `AdminDayDetail` 与 `DayCorrectionWorkingCopy`；
- day-correction open/get/patch/apply 工作流；
- 图片重生成、候选库选择、上传和单图下线接口；
- `DailyExperienceView` 共享展示组件；
- 当前日期立即替换、未来日期 18:00 排期的服务端决定。

当前证据表明第一版应主要修改前端页面、样式、测试和本交互规格。不要为了新布局重写后端或 OpenAPI；如果确实发现现有契约不能满足某条验收标准，先在交付报告中给出精确缺口和最小接口建议，不要自行扩大服务端范围。
