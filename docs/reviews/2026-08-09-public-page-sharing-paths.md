# Five 公开页面分享路径调研

日期：2026-08-09
状态：本地产品与技术调研；不代表微信、QQ 或生产域名已经完成真实验收

## 结论

Five 的默认分享对象应是当天五行页面，而不是一段系统生成文字。分享入口传递指定日期页面 URL，接收者打开后看到完整五档颜色、穿搭和模特图；日签海报作为适合朋友圈、QQ 空间等图片场景的可选方式。

普通 H5 不能可靠指定“只分享到微信好友、朋友圈或 QQ”。Web Share API 只能请求浏览器或操作系统打开分享选择器，目标列表和最终选择由用户设备决定，网页也不能得知用户选择了哪个目标。因此，页面不得伪造“已分享到微信/朋友圈/QQ”的成功状态。

## 当前源码落地

### 完整页面分享

- 真实用户页的“分享”入口在支持 Web Share API 的浏览器中直接分享精确的 `/daily/{fortuneDate}` URL，并携带 `expectedContentVersion` 与 `channelId`；不再先跳到只展示系统文字的中间页。
- 微信内置浏览器中点击分享时继续停留在完整用户页，提示使用右上角菜单“发送给朋友”或“分享到朋友圈”。这样微信分享的是含完整五档、穿搭和模特图的页面，而不是操作说明页。
- 浏览器不支持 Web Share API 时，原链接进入分享选择页；该页可以复制同一个指定日期 URL，也可以进入海报流程。
- Web Share API 的完成只表示浏览器分享流程已经结束，不证明用户选了微信，更不证明接收方已经收到。

### 海报分享与保存

- 用户进入日签海报页后自动创建并轮询海报任务，不再要求先点击一次“生成”才能开始。
- 后端固定模板先生成版面，再转换为 `1080 × 1440` PNG；新任务的受控素材键和公开 `assetUrl` 使用 `.png`，便于预览、下载和移动端图片分享。
- 切换 PNG 后仍只读兼容历史受控 `poster-*.svg` 素材，避免已经生成的旧海报链接突然变成 404；新任务不会再生成 SVG。
- 渲染器继续识别已发布不可变快照中使用的 `automatic-poster-template-v1`，并用当前固定竖版布局生成 PNG；新结构化内容仍使用当前契约模板版本。
- 海报就绪后，网页先在后台受限预取 PNG 并用 `navigator.canShare({ files })` 判断文件分享能力。支持时，用户点击按钮直接把 PNG 交给系统分享面板；不支持文件分享时，只分享同一指定日期页面 URL。
- 用户仍可下载海报，或在微信中长按海报保存后再发送给好友、群聊或朋友圈。微信内不声称网页能够静默直发图片。

### 已定位的旧流程故障

旧版本地浏览器流程曾出现海报任务持续轮询后失败。根因是 `/today` 返回的已发布图片使用同源相对 URL（例如 `/api/v1/image-assets/...`），旧海报渲染器却只接受绝对 HTTPS URL，最终报 `Published reviewed image URL is invalid`。

当前源码把公开网页源站作为受控同源基准：只允许精确的公开图片素材路径解析相对 URL，外部图片仍走 HTTPS 来源白名单和私网阻断；这修复了相对 URL 与渲染器策略不一致的问题，没有放宽为任意同源请求。

## 分平台路径

### 手机浏览器

1. 点击“分享当天五行页面”。
2. 浏览器支持 Web Share API 时，从完整用户页直接打开系统分享选择器，载荷只包含页面标题和精确的指定日期页面 URL。
3. 微信、QQ 等应用是否出现由系统、浏览器、安装状态和应用能力决定。
4. 浏览器不支持页面分享时进入分享选择页；用户可复制同一页面链接，复制仍失败时显示可长按选择的链接。

依据：[W3C Web Share API](https://www.w3.org/TR/web-share/) 明确规定分享目标由用户代理提供，网站不能获知可用目标或用户最终选择。

### 微信好友与朋友圈

1. 未接入微信 JS-SDK 时：用户在微信内的完整 Five 页面点击分享，页面提示使用右上角菜单“发送给朋友”或“分享到朋友圈”；也可复制链接后粘贴到聊天。
2. 正式域名、具备相应 JS-SDK 权限的认证公众号和 JS 接口安全域名就绪后：后端为当前 URL 生成 JS-SDK 签名，前端通过 `wx.config` 初始化，再使用 `updateAppMessageShareData` 和 `updateTimelineShareData` 设置标题、链接和缩略图。
3. JS-SDK 的职责是配置微信分享卡片，不是绕过用户操作自动发送。真实发送仍由用户在微信界面确认。
4. 朋友圈更适合日签海报：生成或下载海报后，由用户保存图片并发布；同时保留页面二维码或链接入口。

依据：[微信公众平台 JS-SDK 说明](https://developers.weixin.qq.com/doc/service/guide/h5/jssdk.html)。

### QQ 好友与 QQ 空间

1. 普通浏览器沿用 Web Share API 或复制页面链接。
2. 手机 QQ 内置浏览器可以使用右上角分享菜单。
3. 若以后确认需要 QQ 内定制分享卡片，可在 QQ 环境接入 `mqq.data.setShareInfo`；官方文档要求定制的 `share_url` 与当前页面同域，并支持标题、摘要和分享图。
4. P0 不增加直接调用 QQ/QQ 空间私有接口的专用按钮，避免在非 QQ 环境出现无效入口；是否接入以真实用户分享数据决定。

依据：[腾讯移动 Web 开发平台手机 QQ API](https://open.mobile.qq.com/api/mqq/index)。

## Five 的落地顺序

1. 当前本地阶段：完整用户页直接发起指定日期 URL 分享、复制链接、自动生成 PNG 日签海报并提供文件分享或保存；用户端不显示内部图片数量口径和系统生成长文字。
2. 正式域名确定后：补充 Open Graph 基础元数据，确保普通浏览器、聊天工具抓取时有稳定标题、摘要和缩略图。
3. 认证公众号具备 JS-SDK 权限且微信 JS 接口安全域名可用后：增加服务端签名接口和微信 JS-SDK 卡片配置；不得把 `appSecret`、`jsapi_ticket` 或签名密钥下发到浏览器。
4. 上线前真实验证：微信好友、微信群、朋友圈、手机 QQ、QQ 空间、iPhone Safari、Android Chrome；分别记录“分享面板发起、复制链接、海报保存、落地页打开”，不能把面板打开记作实际分享成功。

- **自动测试**：页面 URL 分享、微信引导、复制降级、海报自动创建、文件预取与 `canShare` 分支共 54 项 Web 定向测试通过；海报渲染、Worker、任务与受控 PNG/SVG 读取共 50 项 Backend 测试通过，另有 2 项条件性测试跳过。完整仓库门禁结果仍以本次开发任务的最终报告为准。
- **本地浏览器**：375px Chromium 中用户页、分享选择页和海报页均无横向滚动；当前已发布内容的新任务实际得到 HTTP 200 的 `image/png`，PNG 文件头、`1080 × 1440` 尺寸和 893331 字节载荷均已读取验证。注入 Web Share 测试替身后，用户页传递精确日期 URL，海报页传递名为 `five-2026-08-09.png` 的 893331 字节文件；真实下载事件成功保存同尺寸 PNG。页面证据见 `output/playwright/public-home-share-final-375.png`、`output/playwright/share-page-final-375.png`、`output/playwright/poster-png-share-final-375.png` 和 `output/playwright/wechat-guide-user-page-final-375.png`。操作系统分享面板使用测试替身，因此不等于真实应用分享成功。
- **真实微信**：未在真实微信内置浏览器、微信好友、微信群或朋友圈完成正式域名验证；也未验证微信对链接缩略图、PNG 长按保存和系统分享面板的具体表现。
