## 本轮架构审查目标

请以生产系统架构师视角检查当前实现是否形成可持续维护的模块化单体，而不是再次重做后台视觉。重点审查：

1. 模块、接口、接缝和适配器是否足够深，复杂规则是否仍散落在控制器、React 页面、Worker 或 PostgreSQL 查询中；
2. 自动生产、18:00 公开切换、发布、替换、下线、恢复与可视化订正的数据流是否一致；
3. `fortuneDate`、`servedFortuneDate`、有效窗口与后台 current/next/calendar/issues 是否使用同一事实源；
4. revision、`If-Match`、幂等键、事务、锁序、Worker 重试与单一 ActiveVersion 是否足以防止并发漂移；
5. 发布状态改变后的缓存失效、失败关闭和故障恢复是否完整；
6. 图片生产、搭配库、上传、单图下线、降级卡片与供应商适配是否解耦；
7. 第一方匿名统计的事件口径、隐私、幂等、保留周期和后台报表读模型是否一致；
8. 单一维护者密码登录、安全事件、紧急控制与恢复能力是否在简单体验和风险之间取得合理平衡；

## Codex 独立复核区

外部结论只有与当前源码、契约、测试或可复现运行证据一致时才会被采纳。ChatGPT Pro 只完成静态审查；后续业务修复和完整门禁均由 Codex 在当前工作区独立完成。

### 总体判断

ChatGPT Pro 的总体方向成立：应保留当前模块化单体和现有深领域模块，以最小补丁修正接缝、读模型、Worker 调度和图片撤回，不应引入微服务、消息总线、CQRS、多租户或独立素材中心。

有明确源码证据通过的部分包括：

- 18:00 用户侧公开切换与 23:00 `fortuneDate` 切换由独立解析器承担；
- `/today` 读取真实已发布版本并失败关闭；
- 发布、替换、下线和恢复保留 ActiveVersion、revision、`If-Match`、幂等、事务、审计和缓存失效意图；
- 普通订正拒绝算法字段，只开放文案和图片语义操作；
- 管理员会话、CSRF、共享限流和密码重置后的会话撤销具有合理边界。

### 试用前应完成的修复

1. **P0：搭配库选择接口稳定 404。** `apps/web/src/app/admin/admin-api.ts` 调用 `/images/{slot}/reuse`，而 OpenAPI 与 `AdminDayCorrectionImageController` 唯一路径均为 `/images/{slot}/library/select`。最小修复只需纠正客户端路径，并增加精确 URL 契约测试和一条真实 UI→HTTP 纵向测试。
2. **P0：全局下线图片仍可通过原始公共 URL 读取。** `PublicImageController` 调用的 `readAssetBinary()` 没有查询全局撤回事件，且返回一年 `immutable`。必须让可撤回公共 URL 在下线后返回 404/410、取消一年 immutable 语义，并在同一纵向测试中证明 `/today` 降级与旧 URL 失效。
3. **P0：自动首发的待检查图片与单图下线规则不一致。** 自动首发保留 `reviewStatus=pending` 并允许公开投影使用非 rejected 素材；但活动必备图下线时，备用图必须通过 `isDeliverableAdminImageAsset()`（要求 `approved + fileUrl`），因此两张正常待检查图片中的任一张可能无法被安全下线。应统一“自动首发可用素材”的投影与撤回口径，并补“自动生成→发布→单图下线→安全降级”测试。
4. **P1（试用前修复）：Worker 周期可能重入。** `main-worker.ts` 使用 fail-fast `Promise.all`，任一任务先失败会提前清除 `cycleRunning`，其他任务仍可能运行。数据库租约降低了同一任务重复执行风险，所以 Codex 将 Pro 的 P0 降为 P1；仍建议改为等待全部任务收敛后再释放 single-flight 标志，并用 deferred promise 测试重入窗口。
5. **P1（试用前修复）：外部生图请求没有超时。** `OpenAiImageGenerator.generate()` 的 `fetch` 没有 `AbortSignal`。它可能长期占住共享 Worker，进程重启或租约过期后还可能重复产生付费请求。应在适配器层增加请求超时、可观察错误分类和稳定测试替身，不把供应商逻辑移入领域模块。
6. **P1（试用前修复）：运营月历不是单一数据库快照。** 42 日读取先查全量生产记录，再逐日、逐版本调用多个各自独立的查询/事务；并发发布时可拼出数据库从未真实存在的混合状态。保留 `AdminOperationsStore.readDays()` 接口，只重写 PostgreSQL 适配器为一个 `REPEATABLE READ READ ONLY` 范围批量读取，并增加并发 barrier 与查询预算测试。

### 采纳但不作为当前架构阻塞

- `admin-api.ts` 与 `admin-operations-ui.tsx` 体积过大，且手写客户端已经导致真实契约漂移；后续应按页面/用户动作拆分，并让 OpenAPI 生成客户端承担 URL 与类型事实源。
- HTTP 与 Worker 默认以 `process.cwd()/.five-assets` 读取图片是正式多容器部署风险；当前单机同目录运行不等于已发生故障，但正式部署前必须冻结共享持久存储、备份和校验契约。
- 日期级安全恢复能力仍藏在高级工作台，应在普通后台提供同日安全版本选择及不可恢复原因。
- 生命周期存在真实但更细的口径漂移：PRD 定义默认 `draft → approved`、历史兼容 `in_review`；代码的 automatic/correction 模式进入 `approved`，standard 模式仍进入 `in_review`，OpenAPI submit 描述也仍写 `in_review`。应明确兼容入口并同步契约和示例，不能简单表述为“实现全部默认 approved”。
- 匿名统计只能作为产品弱信号。HMAC 保护匿名标识，不证明事件来源、真实曝光或微信分享成功；后台必须继续使用“分享发起”等准确名称。

### 对 ChatGPT Pro 结论的修正

- ChatGPT Pro 已在同一对话中逐项接受以下四项复核结果，并撤回 manifest 来源缺口判断；没有保留反驳。
- **否决 manifest 来源缺口。** 包内 manifest 的 SHA-256 为 `cc596ec1ab8db98b4d5e6a56353861fa54447ce9b2edf4008c3394ce66b9fe8e`，外部 manifest 的 SHA-256 为文首记录值。二者不同是预期的两阶段设计：外部 manifest 在 ZIP 生成后追加 `zip_filename`、`zip_size_bytes` 和 `zip_sha256`；去掉这三个字段并规范化后，两者内容一致。包内 manifest 无法自包含 ZIP 自身哈希，否则会形成自引用循环。
- **Worker 重入严重度从 P0 降为 P1。** 机制缺陷成立，但数据库 claim、lease 与 attempt token 已缓解同一任务重复副作用；实际影响取决于一个任务快速失败而另一个任务继续慢跑的异常窗口。
- **匿名统计不是安全来源证明。** Pro 所称 HMAC“证明来源”不成立；它只对匿名标识做不可逆化处理，客户端仍可声明日期、版本、渠道和事件。

### 必补验证

- 搭配库选择的客户端契约测试和真实 UI→HTTP 路径；
- 图片下线前公共 URL 200、下线后 404/410，同时 `/today` 使用安全降级；
- 自动首发 pending 图片的单图下线与两张必备图安全性；
- Worker 一任务立即失败、另一任务保持 pending 时不启动第二周期；
- 生图请求超时、失败分类与不调用真实付费接口；
- PostgreSQL 月历读取在并发发布期间只能得到完整的发布前或发布后快照，且查询数有固定上界。

## 修复与独立验收（2026-08-10）

### 已落地修复

- 搭配库选择统一到 OpenAPI 的 `/library/select`，网页公共 fetch 接缝与真实 Fastify 控制器测试分别锁定请求和响应契约。
- 公开图片只允许读取当前已发布投影实际交付的素材；未发布草稿素材返回 404，全局下线后旧 URL 返回 404 且不缓存，紧急停止也覆盖公开图片路由。
- 单图全局下线会锁定并检查所有日期的活动图片组，不能破坏另一日期共享素材的最后安全必备图；自动首发 pending 素材继续允许安全降级。
- Admin Operations PostgreSQL 适配器改为单个 `REPEATABLE READ READ ONLY` 批量快照，修正全局下线草稿图、可选图口径和跨日期版本指针，并用并发 barrier 验证只返回完整前态或后态。
- Worker 首轮和后续周期都等待所有任务 settle 后再释放 single-flight；常驻进程逐项记录故障，`WORKER_ONCE=1` 仍会在任一任务失败时返回非零。
- OpenAI 图片适配器加入默认 60 秒可注入超时和稳定错误码；测试只使用 fake fetch，没有调用付费接口。
- 图片任务完成改为基于事务内锁定的当前草稿 revision 继续 CAS，避免无关修订竞争后遗留 claimed job 并在租约后重复付费生成。
- 生产状态的两份 PostgreSQL 投影都排除全局下线素材；关键 production-current 集成套件加入门禁，并使用单独的一次性数据库避免测试数据互相污染。
