# P0 匿名使用统计与试用反馈闭环实施规格

> 状态：issue-ready，本地实施基线
> 日期：2026-08-09
> 远程操作：本任务未授权创建 GitHub Issue、提交、推送或部署

## 背景与目标

Five 即将进入 10 至 20 名普通用户、连续 7 天的受控试用。试用需要回答四个问题：用户是否真的打开、是否进入搭配、是否主动发起分享、分享后是否带来新的落地访问。现有公开页面具备浏览、搭配、分享和海报能力，但没有匿名行为事件、回流归因或后台统计。

本次只实现 P0 最小反馈闭环，不建设通用 BI、用户账户、跨设备身份、广告归因、联系人关系、积分或分享解锁。

## 事实源与不可破坏边界

- `docs/product/prd.md` 第 16.4、21.3、22.1 节；
- ADR-0028 的 18:00 `servedFortuneDate` 与 23:00 `fortuneDate` 双时间轴；
- ADR-0030 的独立“数据”入口、7/30 日真实报表与图表口径；
- `docs/api/openapi.yaml` 先于实现更新；
- 后台一级导航为“今日、日历、数据、异常”；
- 埋点失败不得阻止 `/today`、搭配、分享、海报或后台运营视图；
- 统计只描述可观测动作，不把系统分享面板结束、下载触发或外部转发称为成功发送；“保存成功”只来自用户在下载尝试后的明确确认。

## 第一版事件

第一版接收下列既有 P0 事件：

- `view_today_summary`；
- `open_outfit_hub`；
- `view_daily_look`；
- `view_look_detail`；
- `share_summary_initiated`；
- `share_link_landing_view`；
- `share_poster_initiated`；
- `poster_save_requested`；
- `poster_save_succeeded`；
- `poster_save_failed`；
- `poster_landing_view`。

每条事件携带 `eventId`、当前浏览器随机 `anonymousId`、服务端内容中的 `fortuneDate` 和实际交付 `contentVersion`、可空的分享来源 `sourceContentVersion`、`channelId`，以及可空的 `referralId`、`posterInstanceId`。事件不得携带账号、联系人、群、原始 IP、完整 User-Agent、出生信息或任意自由文本属性。

`anonymousId` 只在浏览器本地生成；服务端使用独立 HMAC 密钥后再持久化，不保存原值。普通链接分享的 `referralId` 是一次出站分享生成的独立随机引用；海报使用公开的海报任务 ID 作为稳定引用，使图片内二维码、系统文件分享与落地页使用同一键。两者都不得包含 `anonymousId`，只用于把分享发起与后续落地访问相连。

## API 与数据模型

### `POST /api/v1/analytics-events`

- 通过以 `eventName` 为判别字段的 OpenAPI `oneOf` 与服务端校验严格约束事件字段；普通浏览、分享、海报保存和落地事件不得互相夹带无关属性；
- `eventId` 与规范化请求哈希共同实现幂等；同一载荷重放不增加统计，不同载荷复用同一 ID 返回冲突；
- 成功或相同载荷幂等重放均返回 `202 accepted | duplicate`；
- 单浏览器和全局事件预算超限返回稳定 `429 RATE_LIMITED`；每个进程最多允许两条并发统计写入，避免旁路能力耗尽核心数据库连接；
- 写入失败返回稳定 `503 ANALYTICS_UNAVAILABLE`，网页调用方必须吞掉该错误；HMAC 配置缺失只停用采集，不阻止用户端或 Worker 启动；
- 响应 `Cache-Control: no-store` 并返回 `X-Request-Id`。

### `GET /admin/api/v1/analytics/overview`

- 需要后台会话；
- 按 `from`、`to` 和可选 `channelId`、`contentVersion` 查询，日期范围最多 31 日；
- 返回采集状态、PV、匿名浏览器数、进入搭配人数、搭配详情人数、分享发起次数、分享发起人数、由另一浏览器打开且能匹配发起事件的回流人数，以及海报保存请求、用户确认成功与已知失败数；
- 返回与筛选范围一致的连续每日序列和渠道 PV 聚合，供最近 7 日或 30 日报表使用；真实零事件日期仍必须出现在序列中；
- 比率同时返回分子、分母与可空比率；分母为零时显示“暂无数据”，不得伪造 `0%`；
- 后台响应 `Cache-Control: no-store`。

渠道分布只能用可加总的 PV 计算。同一匿名浏览器可能跨多个渠道，分渠道匿名浏览器数相加会重复，不能作为饼图整体。搭配查看、分享发起和回流使用并列柱状趋势，不称为严格漏斗，也不暗示每根柱都来自同一批浏览器并按固定顺序发生。

PostgreSQL 新增追加式 `analytics_events` 表，保存 HMAC 后的匿名摘要、规范请求哈希、内容日期、实际内容版本、可空来源版本、渠道、可空分享引用与服务端接收时间。数据库约束再次校验事件语义；Worker 清理超过 90 天的原始事件，聚合或延长保留策略另行评审。

## 前端触发与展示

- 有效公开首页真正显示后记录 `view_today_summary`；后台复用的用户端预览不记录；
- 搭配入口和成功落地页记录对应事件；
- 分享按钮先发起不等待结果的 `sendBeacon` 或 `keepalive fetch` 旁路上报，再立即调用系统分享能力，不能因等待埋点丢失移动端用户激活；
- 首页入口渠道贯穿搭配列表、详情和分享；出站用户分享统一使用 `channelId=user_share` 并附加 `referralId`；落地成功后带相同引用记录页面访问；
- 海报二维码和海报页分享使用同一公开任务 ID；微信内点击分享时先把当前地址改为带归因的完整当日页，再提示使用右上角菜单；
- 后台“今日”页可保留精简的“今日使用情况”和“查看完整数据”入口，统计失败只让该区域显示暂时不可读取，不影响内容健康、预览与订正；
- 新增独立“数据”一级入口，默认显示最近 7 个服务端内容日期，并允许切换最近 30 日；
- 数据页使用折线图展示 PV 与匿名浏览器趋势，使用柱状图展示搭配查看、分享发起和可验证回流，使用饼图展示渠道 PV；
- 图表必须有可访问名称、图例和等价数值说明，375px 宽度不得产生页面级横向滚动，范围切换和主要操作不小于 44×44px；
- 只展示真实聚合。整个范围没有事件时显示“暂无真实访问数据”；采集未配置、读取失败或响应不完整时显示“统计暂不可用”并隐藏不完整数字与图表，不得使用 demo、随机趋势或固定零值补位；
- 已知渠道使用维护者可理解的中文名称，未知渠道合并显示为“其他”；普通页面不展示原始 `channelId`、`contentVersion`、事件 ID、HMAC、JSON 或内部错误。

## 隐私与退出

- 帮助页必须在启用前说明用途、保存期限、第一方随机标识和不收集内容；
- 提供“停止匿名统计并清除统计标识”；退出标志保留在本机，避免下一次访问自动重建标识；
- “清除本机 Five 数据”同时删除内容缓存、匿名标识和会话标识，但不删除退出标志；
- 未接入第三方统计 SDK、分析 Cookie 或设备指纹。

## 测试接缝

1. 公开事件接口：合法事件可接收、重复 `eventId` 不重复统计、非法或多余字段被拒绝、存储失败不泄漏内部信息。
2. 后台报表接口：7 日和 30 日范围返回连续每日序列与真实零值日期，区间总计、每日序列和渠道 PV 使用同一筛选口径；零分母返回 `null`，未认证拒绝。
3. 独立数据页：顶部与侧边导航正确标记“数据”；7/30 日切换只读取真实报表；折线、柱状、饼图具有可访问名称与等价数值说明；无数据和采集不可用明确区分；普通页面不暴露内部标识。
4. 浏览器行为：退出统计时不发送；发送失败不影响页面、导航或分享；后台预览不产生 PV；分享取消仍只记录“发起”。
5. 真实流程：两个隔离浏览器上下文完成“打开首页 → 查看搭配 → 发起分享 → 带 `referralId` 落地 → 后台读取汇总”，并在 375px 下确认数据页无页面级横向滚动。

## 验收

- OpenAPI、生成类型、后端、网页与后台使用同一事件名和字段；
- 后台能看到真实 PV/匿名浏览器数、搭配转化、分享发起和分享回流；
- 后台可从一级“数据”入口查看最近 7 日或 30 日真实趋势和渠道 PV 分布；行为柱状图不标为严格漏斗；
- 无真实事件、采集未配置和聚合读取失败分别显示正确状态，不使用 demo 或误导性零值；
- 任何页面不出现“实际微信分享成功量”；
- `pnpm check`、`pnpm smoke` 和相关本地流程通过；
- 未调用付费生图接口；
- 未提交、推送、部署或修改生产数据。
