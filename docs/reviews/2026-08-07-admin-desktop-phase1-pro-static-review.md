Codex 后续独立审查否定了初次候选的可验收状态，发现了后端 generator/copyVersion 越界修改、`overflow: hidden` 破坏 sticky，以及订正权威数据、保存并发与图片请求竞态等问题。修正版必须另行复核并通过真实本地测试；不能沿用上述初次判断。

## Pro 初次判断的六项边界

1. 1440px 桌面页面以结构化表单为编辑主体；真实用户端预览只用于核对和定位。
2. Pro 当时判断多字段输入会顺序使用最新 ETag 保存并只调用一次 apply；后续 Codex 独立审查找到了保存期间继续编辑导致数据丢失的可复现序列，因此此项初次判断不成立。
3. `preview=null` 时不自动创建订正、不拼演示用户页、不生成空白文字表单；图片维护入口仍可使用。
4. 两张必备图齐全时，可选图 `failed` 或 `not_requested` 不阻塞生效。
5. 1024px 以下把预览降级为抽屉，375px 以下使用全屏核对视图；编辑事实源仍是结构化表单。
6. 新测试覆盖桌面独立编辑、多输入保留、顺序 ETag、单次 apply、可选图不阻塞和缺预览场景。

## 独立复核与修正循环

Pro 的静态复核不能替代源码和运行验收。Codex 在后续逐轮复核中发现并修正了以下实际问题：

1. 初次候选越界修改了后端 generator 与 `copyVersion`，并用 `overflow: hidden` 破坏了 sticky；已撤销越界改动并改用不建立滚动容器的裁切方式。
2. 后台表单没有随输入实时更新真实用户端预览，且服务端工作副本、图片槽位和本地 dirty 输入之间存在回填漂移；已统一重建和协调规则。
3. 多字段保存期间继续输入可能丢失，旧图片请求可能覆盖新槽位，同日权威刷新可能让表单和预览漂移；已增加同步 ref、保存快照、请求 revision 和权威协调测试。
4. 后台刷新失败会卸载正在编辑的页面，apply 成功后也可能错误等待旧 authority；已保留 ready 页面和本地输入，并用生命周期、ActiveVersion 或预览内容版本确认解锁。
5. 更高权威版本 `rev5/v3` 先于 apply 响应 `rev4/v2` 到达时，旧订正曾会重新叠到新版本；现在确认后直接从收到的权威 detail 重建编辑器和手机预览。
6. apply 成功后原实现没有主动重新读取 authority，用户停留当前页时可能锁定到下一个业务边界；现在由日期加载器立即发起一次权威读取，失败仍保留页面和锁，并可在页面重新可见时重试。

最终代码经两轮独立只读复核，未发现可复现 P0、P1 或 P2。Pro 对最后两次修正的结论同样为“无可复现 P0/P1/P2”，但它只审查了 Codex 提供的准确修正说明，没有读取最终本地 diff，也没有执行测试，因此最终通过仍以 Codex 的实际源码和运行证据为准。
