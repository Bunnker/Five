# Five P0 接口说明

本目录回答一个很实际的问题：网页、后台和后端之间到底传什么，谁可以改什么，内容变化后客户端应该怎么办。

## 唯一事实源

[openapi.yaml](openapi.yaml) 是 P0 接口的唯一事实源。后续工程建立后：

- 后端按它实现请求、响应和错误；
- 网页和后台从它生成 TypeScript 类型；
- 自动检查用它核对示例和真实响应；
- PRD 解释用户价值和业务规则，不再重复维护另一套字段定义。

如果 PRD 示例与 OpenAPI 不一致，以 OpenAPI 为准，并在同一个修改中修正 PRD。不能只改前端类型或后端代码。

## 普通用户会用到的接口

| 用户行为 | 接口 | 用人话解释 |
|---|---|---|
| 打开今天 | `GET /api/v1/today` | 后端从同一时刻算出民用日期、23:00 命理日、时辰和 18:00 切换的 `servedFortuneDate`，并返回当前公开交付日的完整内容 |
| 打开群里的旧链接 | `GET /api/v1/daily/{fortuneDate}` | 返回指定命理日当前仍安全的内容；原版本变化时说明为什么换成了新版本 |
| 查看一套穿搭 | `GET /api/v1/daily/{fortuneDate}/looks/{lookId}` | 必须带页面当前的 `contentVersion`；版本变化时要求整页刷新 |
| 生成日签海报 | `POST /api/v1/poster-jobs` | 使用已发布内容和已审核图片渲染，不在用户访问时调用 AI 生图 |
| 提交纠错 | `POST /api/v1/feedback-reports` | 提交内容问题或产品建议，联系方式默认不填 |
| 记录匿名使用动作 | `POST /api/v1/analytics-events` | 旁路记录打开、搭配、分享发起和回流；失败不影响用户操作，不保存原始匿名标识或分享目标 |

所有公开读取接口都只返回已经发布的内容，不会返回草稿、大师确认截图、内部备注、图片权利材料或后台状态。全局紧急开关关闭时，每日内容、搭配、海报任务和源站海报素材统一返回 `503 PUBLIC_ACCESS_STOPPED`；帮助说明、反馈和健康检查仍可使用。已经下载或被外部转发的副本无法由源站召回。

匿名统计使用浏览器随机第一方标识，服务端只保存独立 HMAC 摘要。普通分享链接中的 `referralId` 是每次分享独立生成的随机引用；海报二维码使用公开海报任务 ID 作为同一张海报的稳定引用；两者都不得复用匿名标识。海报保存成功只统计用户在下载尝试后的明确确认。

后台“今日”页通过 `GET /admin/api/v1/analytics/overview` 读取当前内容日期的精简摘要；独立“数据”一级入口通过 `GET /admin/api/v1/analytics/report?days=7|30` 读取对应范围的真实报表。报表包含区间摘要、连续每日序列和按渠道聚合：折线图展示访问趋势，柱状图展示搭配查看、分享发起和可验证回流，渠道饼图只按可加总的 PV 计算。行为柱状图不是严格漏斗；这些数据不表示微信实际发送成功，也不构成真实个人或跨设备用户身份。完整字段、筛选和示例仍只以 [openapi.yaml](openapi.yaml) 为准。

没有真实事件时，接口和页面不得填充 demo 或随机趋势；采集配置缺失或聚合不可用时，普通后台隐藏不完整图表并显示“统计暂不可用”，且不影响今日内容、日历、异常或公开页面。

## 维护者会用到的接口

后台流程固定为：

1. 从服务端按命理日找回未完成草稿，或创建新草稿；
2. 分别编辑日历算法、文案搭配、图片权利和海报一致性四部分；
3. 图片候选齐备后提交草稿，直接生成不可修改且可发布的 `contentVersion`；
4. 当前 `servedFortuneDate` 立即发布，未来公开交付日按 `PublicContentWindowResolver` 给出的 `effectiveFrom` 排期；
5. 维护者和大师查看用户端效果，发布后补充检查、权利、AI 标识和意见；
6. 有问题时从当前版本复制新草稿，发布新版本并替换旧活跃版本；
7. 必要时下线问题版本，或者恢复同一天曾经发布的旧版本。

图片先绑定 `draftId + fortuneDate`，提交时绑定 `contentVersion`。multipart 的 `metadata` 使用不带 filename 的普通字段，字段值为契约对象的 UTF-8 JSON 文本。每次上传必须提供非空来源材料与权利记录引用，来源类型只能与契约规定的生成方式组合。两个必备槽位各自冻结与原封面不同、已审核且可安全交付的降级素材；原图初始不合格时直接使用降级素材，不伪造下线事件。上传和逐图审核都使用草稿 ETag、CSRF 与幂等键；从旧版本复制到新草稿的素材返回 `reviewLocked: true`，不得跨草稿改写原审核，维护者需要调整时上传新素材。单图下线使用生命周期 ETag 与幂等键，并只追加交付事件，不改写快照；同一 `assetId` 的下线是全局事实，所有引用它的旧版本读取时都重新计算交付投影，不能复活同一公共 URL。活跃版本的必备原图和降级图不能同时失去交付能力；非活跃版本若两者都被全局禁用，则该必备槽位明确返回 `deliveryStatus: unavailable`，并阻止其安全恢复。

待审核图片通过 `GET /admin/api/v1/image-assets/{assetId}/preview` 在后台预览。这个地址要求当前后台会话并固定 `no-store`，不会写入公开内容；公开 `fileUrl` 只有在内容已发布且当前图片交付投影仍允许时才能由公共素材入口提供。

本地验证在 `fileUrl` 尚未冻结时通过公共只读图片入口 `/api/v1/image-assets/{assetId}` 交付内容版本引用的不可变文件；人工检查不再阻止首次发布。公网仍应配置合法 HTTPS `FIVE_PUBLIC_ASSET_BASE_URL` 和内容加速，具体对象存储实现由部署任务决定。

未完成草稿通过 `GET /admin/api/v1/daily-content-drafts` 从 PostgreSQL 读取，并可用
`fortuneDate` 筛选；浏览器本地存储不保存草稿编号、大师凭证或并发修订号。

后台只有一个维护者，不存在“创建者不能审核”“必须由另一个角色发布”之类的多人限制。Issue #37 已确认以下安全入口：

1. 账号首次由本机交互式命令从 stdin 创建，不存在注册、默认密码或通过 HTTP 初始化；
2. 登录以账号和至少 8 位密码直接建立会话，不提供默认密码；
3. 会话使用同源安全 Cookie，闲置 30 分钟、绝对 12 小时失效；写操作同时检查可信 `Origin` 和会话绑定的 `X-CSRF-Token`；
4. 忘记密码只允许服务器管理员运行交互式离线重置，重置撤销全部会话；
5. 登录、离线重置、退出、限流和紧急控制写入至少保留 365 天的安全记录，维护者可在后台查看；
6. 停止与恢复全部公开内容要求安全会话、精确确认短语、原因、紧急开关 ETag 和 `Idempotency-Key`。

密码使用校准后的 scrypt；会话只保存域分离摘要。凭据原文不得进入日志、示例、迁移或环境文件。

迁移完成后，本地首次建号运行 `pnpm admin:bootstrap`；只有凭据库为空时才会成功。拥有服务器和数据库权限的人执行离线重置时运行 `pnpm admin:reset`。两个命令都要求交互式 TTY，密码只从隐藏的 stdin 读取。正式环境可在已经安全注入环境变量的 shell 中直接运行后端的 `admin:credentials` 命令，不把秘密拼进命令行。

后台进程和离线命令需要以下部署配置，但仓库只记录变量名，不保存示例密钥或正式值：

- `FIVE_ADMIN_HMAC_KEY_BASE64`：独立的 32 字节随机 HMAC 密钥，经 Base64 编码；
- `FIVE_ADMIN_TRUSTED_ORIGINS`：逗号分隔的后台网页精确 Origin，不接受通配符、路径或携带账号的 URL。

旧数据库中的 TOTP 与恢复数据仅为迁移兼容而暂留，不参与登录、初始化或离线重置，也不再需要运行时加密密钥。

`pnpm local:setup` 只会在被 Git 忽略的本地 `.env` 中生成开发密钥并收紧文件权限；正式密钥必须由部署任务另行生成、托管、轮换和备份，不得复制本地值。

## 四种版本保护

这些名字看起来相近，但处理的问题不同：

| 保护 | 什么时候使用 | 发生冲突时 |
|---|---|---|
| `contentVersion` | 网页从每日内容进入穿搭详情或海报 | 返回 `409 CONTENT_VERSION_CHANGED`，网页整包刷新 |
| 草稿 ETag | 维护者修改草稿、上传图片或逐图审核 | 返回 `412 REVISION_MISMATCH`，重新加载草稿后再改 |
| 生命周期 ETag | 批准、排期、发布、版本下线、单图下线和恢复 | 返回 `412 REVISION_MISMATCH`，重新加载当前状态后再操作 |
| 紧急开关 ETag | 停止或恢复全部公开内容 | 返回 `412 REVISION_MISMATCH`，重新读取全局开关后再确认 |

图片上传、逐图审核、提交草稿、批准、排期、发布、版本下线、单图下线和恢复都必须带 `Idempotency-Key`。网络重试复用同一个键，避免重复创建素材、审核、版本、事件或发布；同一个键如果带了不同内容，返回 `409 IDEMPOTENCY_KEY_REUSED`。

`fortuneDate` 仍在北京时间 23:00 切换并服务干支、五行与时辰算法；`servedFortuneDate` 独立在 18:00 切换并决定 `/today`、后台 current/next 和自动发布选择哪一天。命理日 `D` 的公开窗口固定为 `[D - 1 日 18:00, D 日 18:00)`，准备截止为前一日 13:00。18:00 缺少新日安全内容时公开读取 fail closed，不能继续交付已越过 `effectiveTo` 的旧版本。

`expectedActiveContentVersion` 用来防止后台旧页面覆盖当前公开版本。它与 ETag 不是一回事：

- ETag 保护“我看到的这条记录有没有被修改”；
- `expectedActiveContentVersion` 保护“这个公开交付日当前公开的是不是我以为的版本”。

## 已冻结的内容

- `contentVersion` 是不透明字符串，只能比较是否相等；
- 内容状态只有八个：`draft`、`in_review`、`changes_requested`、`approved`、`scheduled`、`published`、`superseded`、`withdrawn`；
- 每日内容固定返回五条档位记录；网页按 `rank` 排序并使用 `algorithmLabel` 直接显示“大吉、次吉、平、较差、不利”；
- `displayLabel: "注意"` 和 `displaySection: "attention"` 保留为兼容与布局分组元数据，不得用来把 `jiao_cha`、`bu_li` 的可见标题合并成“注意”；这项展示调整不修改 OpenAPI wire contract；
- 平衡建议单独返回，适用于已经穿了较差或不利档颜色的用户，并始终只推荐大吉色普通配饰的小面积补充；
- 正常每日图片组恰好有 `required_primary` 和 `required_alternative` 两个必备封面槽位，最多一个 `optional` 封面槽位；各槽位封面素材分别唯一，每个必备槽位都冻结不同于原图的审核降级素材，细节图和降级素材不计入 2+1；
- 公开图片与后台图片字段分开，公开端看不到文件校验值、权利记录或内部检查状态；
- 后台图片保存供应商无关的生成方式、至少一个来源材料引用、至少一个权利记录引用和结构化人工检查；AI 图片必须有模型、提示词版本、生成时间和重现引用，非 AI 图片的相应生成字段可以为空；当前交付细节图必须恰好是冻结细节集合中可交付且未下线的部分；
- P0 不再传 `platform`、`sourcePlatform` 和 `targetPlatform`；只有需要区分链接来源时才使用 `channelId`；
- 网页版本变化、后台修订冲突和活跃版本变化使用不同错误码，不能都叫“版本错误”。
- 所有后台响应（包括业务内容和错误）一律 `Cache-Control: no-store`，避免退出后从缓存读取核对凭证；生产会话 Cookie 固定为 `HttpOnly; Secure; SameSite=Strict; Path=/admin` 且无 `Domain`；
- 登录在正文解析前先按单向请求来源指纹进行 PostgreSQL 限流；账号级限流在严格解析并规范化账号后、昂贵密码校验前执行，不存在的账号也按唯一账号当前哈希参数执行等价工作量校验；
- Next.js 只提供同源 `/admin/api` 转发，不向浏览器暴露后端地址或把 CSRF 令牌写入 localStorage；进入受信 loopback rewrite 前先删除客户端伪造的标准代理转发头，正式入口代理与 CIDR 仍由 Issue #34 验收。

## 仍需在部署任务决定的事

- 美国服务器、域名、图片存储和内容加速服务；
- 域分离摘要密钥的正式密钥托管与轮换方式；
- CDN 如何在紧急停止时执行 `purge/deny`，以及真实中国大陆网络中的传播时间。

这些部署事项不能反向改变本契约中的登录、日期、内容、状态、图片和版本含义。若密码丢失，只允许具备服务器与数据库权限的人运行离线重置命令；重置仍须注销全部会话并追加安全审计，不能临时增加短信或邮箱后门。

## 修改规则

1. 先在 GitHub Issue 中说明为什么现有接口不能满足需要；
2. 修改 `openapi.yaml` 和对应示例；
3. 运行 OpenAPI 校验；
4. 同步 PRD、领域词汇和受影响 ADR；
5. 接口已经对外使用后，破坏兼容性的修改必须增加接口版本，不能静默改写 `/api/v1`。
